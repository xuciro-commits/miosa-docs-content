**发布**是构建生成的不可变工件。版本参考版本；静态部署从它们提供文件，动态部署从它们启动运行时。

您通常不会直接通过 API 处理发布问题。它们是 `Deployment Version` 的实现细节。但知道它们作为自己的记录存在是很有用的，因为它们是回滚和水平扩展工作的基础。

> **注意：调用者合约**
>
> 大多数集成不需要直接读取发布记录。使用部署版本和返回的部署 `public_url` 除非您正在构建操作员仪表板或审核工作流程。

## 发布类型

|亲切 |使用者 |存储|
|---|---|---|
| `static` |静态部署 |构建文件和资产|
| `oci` |通过兼容 OCI 的工作流程进行动态部署 |服务器镜像产物|
| `dynamic` |具有运行命令和端口的服务器应用程序 |打包服务器产物|

发布格式决定了部署的服务方式：

- **静态发布** → MIOSA 的静态工件服务器直接从对象存储流式传输文件。没有运行每个应用程序的进程。
- **动态发布** → MIOSA 启动健康的生产运行时间并将流量路由到它们。

## 不变性

发布内容由 sha256 寻址。具有 sha256 `abc...` 的版本始终是相同的字节，无论在何处引用。这就是为什么：

- **回滚**琐碎：将域重新指向旧版本，该版本仍然引用其版本。
- **扩展**琐碎：在 N 个主机上安排同一版本的 N 个副本；每个实例都是字节相同的。
- **审计**清理：可以从其哈希值中重现在时间 T 提供流量的版本。

版本在创建后永远不会发生变化。要“更改”它，请发布一个新版本，这会产生一个新版本。

## 发布地点

版本由 MIOSA 存储和提供。您可以检查版本记录上的发布元数据：
```json
{
  "version_number": 17,
  "artifact_sha256": "a5e6f0c1...",
  "artifact_manifest": {
    "files": 42,
    "total_bytes": 184320,
    "entrypoint": "index.html"
  }
}
```

您不需要自己下载版本。显示元数据以供调试和审核。

## 源快照与发布版本

这是同一构建中的两个不同的工件：

|产物|它是什么 | Sha256 存储于 |
|---|---|---|
| **源快照** |发布时沙盒源代码的冻结 tarball | `version.source_sha256` |
| **发布** |构建的输出 | `version.artifact_sha256` |

源快照存在，因此重试/重建是可重现的。该版本的存在是为了可以服务和扩展生产。

## 垃圾收集

早于保留窗口（存档版本默认为 30 天）的静态发布工件可能会被垃圾收集。版本行保留供审计；如果您尝试回滚到其工件已被 GC 处理的版本，MIOSA 将返回 410 Gone。

活动版本（任何部署上的 `active_version_id` 永远不会被 GC，即使是过去的保留也是如此。
