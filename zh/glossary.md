每个 MIOSA 资源、API 字段和计费术语的简单语言定义，以及每个资源的可共享链接。在[产品模型](/docs/concepts)中查看它们如何组合在一起。

## 核心原语

您创建、构建、发布和运行的事物。

### 应用程序引擎主机

App Engine 主机是一个工作区的一台永远在线的机器，它的许多应用程序作为单独的容器运行。

当工作区发布大量小型应用程序、渠道或客户端站点并且为每个应用程序、渠道或客户端站点创建新的生产虚拟机时，使用它会很浪费。 MIOSA 仍然单独对每个部署进行路由、保护和计量。

在 MIOSA 中，Northwind Agency 工作区拥有 15 个客户端站点，所有这些客户端站点都在一台 App Engine 主机上运行。主机是容量，而不是访问边界。

相关：部署、工作区、运行时实例、主机、App Engine

### 产物

工件是值得从构建、命令、评估或智能体运行中保留的文件或结果：报告、屏幕截图、构建文件夹、CSV。

使用工件将输出交给人们。沙箱保留工作表面；您可以准确导出用户应接收的路径，而不是要求他们抓取终端输出。

在 MIOSA 中，智能体写入 `/workspace/artifacts/report.pdf`，您的后端调用该路径的导出，然后您的用户单击“下载”。保存的沙箱状态是快照，发布的应用程序是发布。

相关：快照、发布、智能体运行

### 后台进程

后台进程是您在沙箱中启动的命令，该命令会自行运行，例如开发服务器或长时间作业。它的输出被保留，以便您以后可以阅读。

将 `exec` 用于等待其结果的命令，以及服务器的后台进程和任何长的进程。

在 MIOSA 中，`miosa process start my-box --name api -- node server.js` 启动一个，`miosa ps` 列出正在运行的内容。

相关：执行、沙箱、流执行、预览、日志

### 构建

构建安装依赖项并将源代码编译或打包成可以运行的东西。 MIOSA 在与冻结源快照隔离的构建器中执行此操作。

您主要让 MIOSA 选择：它检测 Dockerfile、语言清单或纯静态文件。当默认值不正确时，使用构建命令覆盖。

在 MIOSA 中，`miosa deploy builds team-portal` 列出部署的构建，失败的构建会使旧版本保持不变。

相关：生成器、发布、发布、Dockerfile、BuildSpec

### 生成器

构建器是处理一次发布的独立工作人员。它获取冻结的源代码，运行构建，存储结果，然后退出。

你很少直接触摸它。这就是为什么构建不会受到您同时在沙箱中所做的任何事情的影响，以及为什么构建是可重复的。

在 MIOSA 中，Lumen 团队门户的发布会启动一个构建器，它会安装依赖项、运行构建命令并生成版本。发布期间，构建器时间以秒为单位计费。

相关：发布、发布、构建、构建规范

### 构建规范

BuildSpec 是一个小型 JSON 文档，它覆盖 MIOSA 的沙盒或部署的默认安装、构建和启动命令。

当自动检测猜测错误时使用它，例如具有不寻常构建步骤的 monorepo。

在 MIOSA 中，BuildSpec 可以将 `install` 设置为 `pnpm install --frozen-lockfile`，将 `build` 设置为 `pnpm build`，将 `start` 设置为服务器命令以及环境变量。

相关：构建、构建器、动态部署、模板

### 检查点

检查点是一个快速的沙箱本地还原点。在执行危险步骤（例如升级依赖项）之前采取一项措施，并在该步骤出错时从中恢复。

快照是机器的可移植历史记录，也是分叉的基础。检查点是快速、就地的检查点。当您想要移动或复制计算机时使用快照，并使用检查点进行快速撤消。

在 MIOSA 中，`miosa checkpoint create my-box --comment "before deps"` 取 1。

相关：快照、恢复、命名快照、沙箱

### 电脑

计算机是一个持久的云桌面：一台真正的 Linux 机器，带有屏幕、浏览器、文件和 shell，您或智能体可以操作该机器，并且在停止时保持其状态。

当工作依赖于像素或会话时，请使用其中之一：单击网站、登录的浏览器、桌面应用程序或人工接管智能体停止的位置。对于代码和构建来说，沙箱更便宜、更快。在 MIOSA 中，Northwind Agency 操作员看着智能体在计算机上填写客户的 Web 表单，然后接管同一桌面来完成。尺寸从 `xs` 到 `xl`，`small` 是默认值。

相关：桌面会话、MIOSA 管理的计算机、OpenComputer、准备情况、能力、计算机使用

### 容器镜像

容器镜像是一个已经构建和打包的应用程序，发布到 GitHub 容器注册表或 Docker Hub 等注册表。

当您在其他地方构建应用程序并且只希望 MIOSA 运行它时，请使用它。 MIOSA 提取镜像并启动它，无需构建步骤。私有注册表需要注册表秘密。

在 MIOSA 中，`miosa service deploy shop API --image ghcr.io/acme/api:1.4 --port 8080` 部署映像。

相关：服务、容器、Dockerfile、构建、发布

### 计划任务

Cron 作业按照您编写为 cron 表达式的时间表运行一个命令，例如每五分钟或每晚凌晨 3 点。

将其用于不需要任何人记住的工作：健康检查、夜间导出、清理。该命令在您附加到的沙箱中运行，因此沙箱需要脚本及其使用的凭据。您还可以立即触发运行来测试它。

在 MIOSA 中，cron 作业是通过 MCP `cron_create` 工具创建的，智能体也可以使用 `miosa agent triggers add` 按计划启动。

相关：沙盒、作业、Webhook

### 部署

部署是应用程序的持久生产标识：其名称、URL、版本历史记录、域、设置和附加数据。部署保持不变，而其背后的代码发生变化。

将其用作“实时应用程序”。当您发布和推广新版本时，相同的部署和 URL 会为新代码提供服务。数据库和存储附加到部署，而不是每个版本。

在 MIOSA 中，Lumen 的 `team-portal` 部署使 `team-portal.example-org.miosa.app` 和自定义域 `portal.example.net` 在每个版本中保持稳定。

相关：版本、发布、升级、域、绑定、环境、运行时实例、静态部署、动态部署、App Engine、服务

### 期望的状态

期望状态是 MIOSA 被告知资源应该是什么样的：正在运行、已停止、按此大小、使用此配置。

这很重要，因为 MIOSA 不断将世界与该记录进行比较。如果主机重新启动而您想要运行的计算机没有重新启动，MIOSA 会将其重新启动而不是等待您。

在 MIOSA 中，您有意停止计算机，并且其所需状态已停止，因此它通过主机维护保持停止状态。正在运行的计算机已恢复并得到验证。

相关：协调、控制平面

### 桌面会话

桌面会话是您用来查看和控制计算机屏幕的实时连接。它是机器的窗口，而不是机器本身。

当您或智能体需要观看、单击和输入时，请使用它。关闭会话会使计算机按原样运行或停止，您可以稍后打开一个新会话。

在 MIOSA 中，支持主管在 Acme Corp 的智能体使用的计算机上打开实时查看器，接管以完成任务，然后在不结束任何操作的情况下关闭查看器。

相关：计算机、准备情况、智能体运行

### Dockerfile

Dockerfile 是一个文本配方，说明如何组装容器映像：基本系统、要复制的文件以及要运行的命令。

如果您的应用程序的输出文件夹中存在该文件，MIOSA 就会根据它构建您的应用程序。您还可以使用它来构建自定义沙箱模板。

在 MIOSA 中，沙箱包含 Docker Engine，因此您可以先在沙箱内测试 Dockerfile，然后通过 App Engine 发布。

相关：容器、构建、模板、App Engine

### 动态部署

动态部署在服务器上运行代码：API、服务器渲染的页面、WebSocket 和后台工作人员。 MIOSA 启动它、检查它并保持它运行。

当应用程序必须根据请求执行工作时选择它。您提供运行命令和端口，以便 MIOSA 知道如何启动和访问它。

在 MIOSA 中，`miosa deploy create --from-sandbox my-box --port 3000 --run-command "npm start" --wait` 发布正在运行的服务器。

相关：静态部署、运行时实例、健康检查、副本

### 环境

环境是新机器的命名启动设置：要克隆哪些存储库、要注入哪些变量和秘密文件以及机器可以使用您的哪些凭据。使用环境，以便每台新的沙箱或计算机都准备好启动，因此登台和生产不会共享设置。每个工作区都有一个名为 `base` 的默认值。

对于部署，部署环境是变量、机密和数据绑定应用的范围。每个项目都有 `production` 和 `staging`，您还可以添加其他项目，例如 `preview/pr-42`。

相关：模板、环境变量、秘密、部署、工作区

### 执行

Exec 在沙箱内运行一个命令并返回其输出和退出代码。例如 `npm install`、`python app.py` 或 `npm run build`。

这就是智能体和脚本完成工作的方式：安装、构建、测试、启动服务器。 CLI 使用远程命令的退出代码退出，因此它直接进入脚本和 CI。

在 MIOSA 中，Lumen 智能体通过 Exec 运行构建并读取输出来决定下一步要修复的内容。一条命令默认30秒，最多300秒；作为后台进程运行更长的时间。

相关：沙箱、作业、事件流 (SSE)、计算机、日志、后台进程、流式执行

### 叉子

分叉会根据现有沙箱当前状态的副本创建一个新沙箱，而原始沙箱仍处于运行状态。分叉后它们是独立的。

使用它在副本上尝试一些有风险的事情，或者为每个客户提供准备好的设置的新副本。

在 MIOSA 中，`miosa fork my-box --ttl 2h` 分叉一个正在运行的沙箱。在原始机器消失后，从命名快照进行分叉也可以工作。

相关：快照、沙箱、暂停和恢复

### 健康检查

运行状况检查是对正在运行的应用程序中的 URL 路径的快速请求。成功响应 (2xx) 表明它是健康的，因此 MIOSA 向其发送流量。

添加一个，这样损坏的版本就不会接管。 MIOSA 仅在实例通过后将流量转移到新版本，并删除停止通过的实例。

在 MIOSA 中，在动态发布上设置 `health_check_path`。静态站点会跳过它，因为没有要检查的应用程序进程。

相关：运行时实例、动态部署、升级、心跳

### 空闲睡眠

空闲睡眠会停止一段时间没有请求的服务，因此当没有人使用它时它不会运行。下一个请求将唤醒它并等待它启动。

它仅适用于具有公共地址的服务，因为请求是唤醒它们的原因。工人和私人服务从不睡觉。在免费计划中，服务始终处于休眠状态。

在 MIOSA 中，使用 `sleep` 设置：`{enabled, idle_s}`。睡眠释放显示状态 `sleeping`。

相关：服务、公共广播、发布、空闲超时

### 空闲超时

空闲超时会在持久沙箱处于非活动状态一段时间后暂停该沙箱，而不是等待固定的超时。

打开它可以节省人们忘记的沙箱的钱。命令、文件写入、预览流量和终端输入都算作活动并重置时钟。

在 MIOSA 中，`miosa create my-box --idle-timeout 15m` 在安静十五分钟后暂停。它仅在您设置时适用，并且暂停的沙箱会根据请求唤醒。

相关：超时、暂停和恢复、预览

### 工作

作业是一个运行的跟踪命令，带有 ID、进度和最终结果（例如退出代码）。

当工作超过一个请求时，这一点很重要：您可以稍后检查它是否完成，或者取消它。在 OpenComputers 上，发送到连接主机的每个命令都是一个作业。

在 MIOSA 中，`miosa host job list <host>` 显示您连接的计算机上最近的命令。取消作业并不能证明远程进程已停止，因此在重试工作（有副作用）之前请先确认结果。

相关：执行、智能体运行

### 日志

日志是沙盒、进程或部署在运行时打印的文本行：启动消息、错误和应用程序自己的输出。

当出现问题时请先阅读它们。在修复问题时关注他们的实时动态。

在 MIOSA 中，`miosa logs my-box -n 100 -f` 遵循沙箱的系统日志，`miosa process logs <pid>` 读取后台进程，`miosa deploy logs team-portal` 读取部署。

相关：执行、构建、事件流 (SSE)、日志消耗

### 命名快照

命名快照是您故意固定在名称下的快照。未命名的快照是机器的历史记录，并会因保留而过期；即使在机器被摧毁之后，命名的机器也会一直保留到您删除该名称为止。将它用于您想要一次又一次开始的设置，然后在需要时从它派生一台新机器。

在 MIOSA 中，每个组织免费保留 10 个命名快照。 `miosa snapshot save my-box web-stack` 引脚 1，并且 `miosa snapshot fork --name web-stack` 从它启动一台机器。

相关：快照、分叉、检查点、模板

### 暂停和恢复

暂停会停止正在运行的沙箱的计算，但保留其磁盘和内存状态。恢复将其带回相同的 ID 和文件，并且进程继续在原来的位置。

使用它可以停止为工作会话之间的计算付费。暂停的 Sandbox 仅按存储费率计费。

在 MIOSA 中，`miosa pause my-box` 和 `miosa resume my-box` 手动完成。暂停的持久沙箱也可以根据请求唤醒：点击其预览 URL 即可恢复它。

相关：持久性、空闲超时、超时、沙箱

### 坚持

持久性意味着沙箱的文件和已安装的工具在停止或暂停时仍然存在。沙盒记录及其 `/workspace` 比任何单个正在运行的会话都存活，直到您销毁它。

将其用于您将要返回的工作：智能体在几天内构建的项目，或客户的工作空间。仅在应该消失的一次性运行时将其关闭。

在 MIOSA 中，沙箱默认是持久的。当超时结束后，持久沙箱将暂停并保留其文件；非持久性的被破坏。

相关：暂停和恢复、超时、快照、沙箱

### 预览

预览是在沙箱内运行的内容的网址。在端口上启动开发服务器，为该端口创建预览，然后您将获得可以在浏览器中打开的 URL。

使用它可以在智能体构建应用程序时观看应用程序，或显示正在进行的工作。预览始终显示沙箱的当前状态，因此它不是生产 URL，并且当沙箱消失时它会停止工作。

在 MIOSA 中，预览类似于 `https://3000-abc12345.sandbox.miosa.ai`。默认情况下预览是私有的；创建一个短暂的共享令牌以允许特定的浏览器进入。

相关：沙箱、预览域、发布、平台 URL、共享令牌、空闲超时、端口转发、沙箱共享

### 预览环境

预览环境是项目的副本，它运行来自一个拉取请求的代码，并具有自己的地址。

打开拉取请求，MIOSA 将默认环境分叉为 `pr-<number>`，部署分支中的每个服务，并注释拉取请求上的地址。关闭或合并它，环境就会被删除。预览永远不会改变它所来自的环境。

在 MIOSA 中，通过命名存储库在项目的 **设置** 下的 **预览** 中将其打开。

相关：环境、项目、服务、预览

### 私人服务

私有服务应答来自同一项目和环境中其他服务的请求，并且永远无法通过互联网访问。

它适合管理后端或仅调用的工作。服务之间的专用网络尚不可用，因此您的其他服务无法通过名称调用它；如果需要的话，给它一个公共地址。

在 MIOSA 中，`miosa service create shop billing --type private --repo https://github.com/acme/billing` 创建一个。服务之间的专用网络尚不可用，因此其他服务目前无法通过名称访问它。

相关：服务、服务类型、私有地址、公共地址

### 项目画布

项目画布是控制台中项目的主视图。它将每个服务、数据库和卷绘制为一张卡片，并显示它们如何连接。

打开卡以更改其设置、变量或域。画布顶部栏中的环境切换器可让您在生产、暂存和预览环境之间切换。

在 MIOSA 中，画布上的编辑变成了暂存更改，并且 **部署** 将它们一起应用。

相关：项目、服务、分阶段变更、环境

### 促销

升级是使一个经过验证的版本成为部署的实时版本的有意步骤。客户继续使用相同的 URL；他们只是开始接收新版本。

用它来区分“构建”和“实时”。发布会产生候选人，您对其进行检查，然后进行晋升。如果出现问题，请升级较早的版本。

在 MIOSA 中，Northwind Agency 客户端站点发布版本 6，检查暂存 URL，然后对其进行升级。域或部署没有任何变化。相关：发布、版本、部署、回滚

### 发布

发布将沙箱当前的作品变成冻结的、可构建的候选作品。 MIOSA 对源进行快照，在隔离的构建器中构建它，并记录不可变的发布和版本。

当应用程序在沙盒中运行并且您想要一个真正的、可重复的生产候选者时，请使用它。构建运行时沙箱可以不断变化。发布本身并不会增加客户流量；促销确实如此。

在MIOSA中，`miosa deploy create --from-sandbox my-box --name team-portal --wait`发布沙箱并等待结果。下次使用相同的名称在同一 URL 后面添加新版本。

相关：构建器、发布、版本、升级、源快照、构建、静态部署、动态部署

### 准备情况

准备就绪证明资源可以完成您现在需要的特定任务。 “创建”和“在线”是不够的。

在发送作业之前检查一下。无头服务器可以准备好运行命令，而无需准备好流式传输桌面，而沙盒只有在`running`后才准备好命令。

在 MIOSA 中，`miosa create my-box --wait` 会阻塞，直到沙箱接受命令，因此 `miosa create x --wait && miosa exec x -- ...` 永远不会竞争。对于主机来说，新鲜的心跳加上完整的命令就是证据。

相关：心跳、证据、计算机、能力

### 和解

协调是自动修复循环：MIOSA 会注意到资源的实际状况与应有的状况不同，并进行修复。

你依赖它而不做任何事。崩溃的运行时被替换，维护中的主机上的计算机被恢复，并且启动丢失的副本。

在 MIOSA 中，当动态 Lumen 应用程序实例终止时，协调器会安排在另一个健康主机上进行替换。手动重新部署与您自己启动的操作不同。

相关：期望状态、控制平面

### 发布

发布是成功发布的最终、不可变的结果：静态站点或打包服务器应用程序的构建文件。它被创建后就永远不会改变。

它回答“我们正在运行哪些确切的字节？”这就是回滚速度快以及许多副本可以相同运行的原因。要更改应用程序，请再次发布以获得新版本。

在 MIOSA 中，Lumen 站点的发布由 sha256 进行内容寻址。切勿通过就地编辑来修复版本；而是发布修复程序。

服务也有版本：每个 `miosa service deploy` 都是一个带有状态的编号的、不可变的版本，并且回滚服务于早期版本的构建映像而无需重建。

相关：发布、版本、部署、工件、服务、回滚

### 恢复

恢复通过从检查点或快照创建新的沙箱来恢复保存的状态。原来的沙箱没有改变，所以可以将两者进行比较。

用它来撤消错误的更改。对于失败或出错的沙箱，`miosa recover` 从其保留的磁盘执行相同的操作。

在 MIOSA 中，`miosa restore my-box cp_abc123` 从检查点恢复并打印新的沙箱。

相关：检查点、快照、分叉、沙箱

### 回滚

回滚将部署返回到早期就绪的版本。它很快，因为没有重建任何内容：旧版本仍然被存储。

当新版本通过检查但在实际流量中表现不佳时使用它，例如错误的迁移或您错过的回归。它恢复已知的应用程序行为，而不是数据。

在 MIOSA 中，Lumen 通过一个命令将 `team-portal` 回滚到版本 16。静态站点数秒内恢复；几秒钟到大约一分钟的动态。数据库更改不会撤消。

相关：促销、版本、发布

### 运行时实例

运行时实例是动态版本的一个运行副本，为一个版本提供流量。静态站点没有它们。

你不能选择他们跑到哪里。 MIOSA 启动实例，等待运行状况检查，将流量路由到运行状况良好的实例，并替换任何失败的实例。一个部署可以有多个容量实例。

在 MIOSA 中，Lumen 的 API 服务器默认作为一个实例运行。发布新版本会首先启动新实例，并且只有在它们运行状况良好时才会移动流量。

相关：部署、版本、发布、App Engine 主机、运行状况检查、副本

### 沙盒

沙盒是云中的私有一次性 Linux 机器。您或 AI 智能体可以在其中安装软件包、运行命令、编辑文件以及启动服务器，而无需接触您的笔记本电脑或生产环境。

将其用作研讨会：在这里构建和测试，然后发布有效的内容。沙盒是可变的，因此它不适合为真正的客户提供服务。发布将副本冻结为不可变的版本。

在 MIOSA 中，Lumen 构建器智能体创建一个沙箱，将 Web 应用程序写入 `/workspace`，启动开发服务器，并打开预览。默认情况下，沙箱是持久的，因此暂停沙箱会保留其文件。

相关：预览、快照、模板、执行、项目、Firecracker、沙箱大小、持久性、暂停和恢复、超时、分叉

### 沙盒大小

沙箱大小是 CPU、内存和磁盘的命名包，例如 `small` 或 `large`。您选择一个名称而不是数字。

选择适合的最小尺寸。 `small`（2 个 vCPU、4 GB RAM、10 GB 磁盘）是默认设置，适合大多数智能体工作、包安装和普通构建。仅当您测量到需要更多时才向上移动到 `medium`。

在 MIOSA 中，`miosa create my-box --size medium` 提供 Sandbox 4 vCPU、8 GB RAM 和 20 GB 磁盘。尺寸越大，跑步时的成本就越高。

相关：沙盒、模板、超时、区域

### 服务

服务是项目运行的一个应用程序，例如您的 API、后台工作人员或静态站点。它属于一个项目和一个环境。

服务的每次部署都会创建一个不可变的版本，您可以回滚到较早的版本而无需重建。服务还具有变量、副本、日志和地址。

在 MIOSA 中，`miosa service create shop API --type web --repo https://github.com/acme/api` 创建一个，然后 `miosa service deploy shop API --wait` 传送它。

相关：服务类型、项目、发布、副本、环境、公共地址、私有地址、共享变量

### 服务类型

每个服务都有一个类型来决定它如何运行以及是否获取地址。

- **Web 服务**：提供 HTTP 服务并且可以拥有公共地址
- **Worker**：无端口无地址运行
- **私人服务**：为项目中的其他服务提供服务，从不提供互联网服务
- **静态站点**：从边缘提供的预构建文件
- **Cron 作业**：五字段计划上的命令，具有运行历史记录
- **数据库服务**：绑定到项目的托管Postgres或Redis

在 MIOSA 中，创建服务时使用 `--type` 选择：`web`、`private`、`worker`、`static` 或 `schedule`。

相关：服务、Worker、私有服务、Cron 作业、静态部署、托管数据库

### 快照

快照是沙盒某一时刻保存的副本。您可以稍后恢复它或从中分叉一个新的沙箱，并且原始沙箱保持不变。

在进行危险的更改之前采取一个措施，或者保留一个可以重复使用的良好起点。快照是开发状态，而不是生产状态：它从不为客户服务。

在 MIOSA 中，Northwind Agency 开发人员设置一个项目一次，将其保存为命名快照，然后为每个新客户端站点创建一个新副本。

相关：沙箱、工件、发布、模板、分叉、持久性、命名快照、检查点、恢复

### 源快照

源快照是沙盒源的冻结存档，在您发布时拍摄。构建是从它运行的，而不是从实时沙箱运行的。

这就是发布可重复的原因：重试可以从完全相同的输入进行重建，并且您可以在构建运行时继续进行编辑。排除构建输出文件夹和缓存。

在 MIOSA 中，发布 Lumen 的站点会将 `/workspace` 冻结为源快照，然后从该副本构建版本。

相关：发布、发布、构建、快照

### 阶段性改变

分阶段更改是您在项目画布上进行的编辑，例如新变量或新副本计数，这些编辑会排队而不是立即应用。底部的栏列出了它们。

选择 **部署** 将它们一起应用，或选择 **放弃** 将它们删除。当项目将更改集保留在服务器上时，Deploy 会立即应用整个更改集：如果一项更改失败，则不会应用任何更改。

在 MIOSA 中，画布上的卡片会显示为其进行了多少更改，因此您可以在发布任何内容之前进行检查。

相关：项目画布、发布、服务、环境变量

### 静态部署

静态部署是由现成文件组成的站点：HTML、CSS、JavaScript 和图像。 MIOSA 直接提供文件服务。没有服务器进程可以保持活动状态。

为登陆页面、单页应用程序、文档和生成的 HTML 选择它。它是最便宜且回滚速度最快的，并且是默认的发布类型。

在 MIOSA 中，`miosa deploy create --dir ./dist --name my-site` 上传构建的文件夹作为静态部署。

相关：动态部署、发布、部署、发布

### 流执行

Streaming exec 运行命令并在发生时将其输出发送给您，而不是等到命令完成。

将其用于构建、安装和测试套件，您希望在其中观察进度或尽早对输出做出反应。

在 MIOSA 中，`miosa exec my-box --stream -- npm test` 流式传输输出，任何超时超过 300 秒的 exec 或 `--timeout 0` 也会流式传输输出。

相关：执行、后台进程、事件流 (SSE)、日志

### 模板

模板是构建新沙箱的起始映像：已安装的操作系统、语言和工具。 MIOSA 为您提供两种内置选择：默认沙箱和桌面，您的组织可以构建自己的沙箱。

选择与您的堆栈最接近的匹配项，以便沙箱在启动时发挥作用。当您不选择一项时，`miosa-sandbox` 为默认值。

在 MIOSA 中，Lumen 团队为其 Next.js 应用程序使用默认沙箱，并在端口 3000 上启动它，或者在需要专有工具链时构建自定义模板。

相关：沙箱、快照、环境、Dockerfile、BuildSpec

### 超时

超时（也称为 TTL）是沙盒的活动会话可以运行的挂钟时间。当它通过时，持久性沙箱将暂停，非持久性沙箱将被销毁。

设置它，使废弃的沙盒永远不会运行和计费。扩展会替换旧值而不是添加旧值，因此请计算出新的总数。

在 MIOSA 中，`miosa create my-box --ttl 2h` 设置两小时，`miosa extend my-box --for 2h` 将其替换为从现在起的两小时。

相关：空闲超时、暂停和恢复、持久性、沙箱

### 版本

版本是部署历史记录中的一个条目。它将一个版本与运行它所需的配置联系起来，并且其数量只会增加。

使用版本来比较、升级和回滚。部署有多个版本，但一次只有一个活动版本，旧版本保持可启动状态，因此返回速度很快。

在 MIOSA 中，Lumen 的 `team-portal` 处于版本 17，而版本 18 正在检查中。通过后提升18；如果没有，则回滚到 17。

相关：发布、部署、升级、回滚、运行时实例

### 工人

Worker 是一种执行后台工作（例如处理队列或发送电子邮件）的服务，但从不响应 Web 请求。

将其用于任何应该继续运行但没有人访问的事情。它没有公共或私有地址，因此其他服务通过共享数据库或队列而不是通过名称来访问它。

在 MIOSA 中，`miosa service create shop jobs --type worker --repo https://github.com/acme/api --start-command "node worker.js"` 创建一个。

相关：服务、服务类型、私有服务、副本

## 组织

### API 密钥

API 密钥是一个秘密，可让软件代表您运行：服务器、脚本、CI、SDK 和 CLI。它在创建时显示一次。

对于无需输入密码即可运行的任何操作，请使用其中之一。将密钥保留在后端，并为浏览器提供短暂的浏览器令牌。将每个键限制在它需要的范围内。

在 MIOSA 中，`miosa api-key create ci --preset ci --expires-in 90` 为沙箱、部署和预览创建了 90 天的密钥。如果钥匙泄漏，请旋转它。

相关：身份验证、浏览器令牌、主机密钥、角色、范围、API 密钥预设、服务帐户

### API 密钥预设

API 密钥预设捆绑了一种常见密钥需求的范围，因此您无需逐一选择它们。

命名的预设为 `read-only`、`ci`、`agent`、`cli`、`automation` 和 `full-access`。预设是一个起点，而不是上限：为它不包含的任何内容添加 `--scope`，并且该键会准确列出它所包含的内容。

在 MIOSA 中，`miosa api-key create ci --preset ci --expires-in 90` 根据预设创建关键点。

相关：API 密钥、范围、服务帐户

### 审核日志

审核日志是操作的记录：谁、何时、何地做了什么。它的存在是为了让你可以在事情发生后回答问题。MIOSA保留两种。活动审核显示您组织中的 API 操作。沙箱的网络审核日志显示工作负载发出的每个出站呼叫。

在 MIOSA 中，`miosa audit` 显示最近的活动，最新的在前。揭示环境价值也记录在那里。

相关：出口、日志、秘密、成员

### 身份验证

身份验证是证明谁在发出请求：具有登录名的人，或者具有 API 密钥或浏览器令牌的程序。

它回答“你是谁？”仅有的。你可以做的是单独检查、授权。

在MIOSA中，每个API请求都携带`Authorization: Bearer <token>`。该令牌可以是 API 密钥（对于服务器）或短期浏览器令牌（对于浏览器）。

相关：授权、API 密钥、用户、双因素身份验证

### 授权

授权是决定一个已经被证明的身份是否可以在特定的地方做特定的事情。

成功登录并不意味着一切都被允许。角色限制人员，范围限制 API 密钥。

在 MIOSA 中，查看者可以读取工作区，但不能创建沙箱，并且没有 `deployments:write` 的密钥无法发布。 API 会告诉您缺少哪个范围。

相关：身份验证、角色、批准

### 反馈

反馈是您向 MIOSA 团队告知错误、缺失功能或任何妨碍您的事情的方式。

从控制台中的 **发送反馈** 发送，您可以在其中附加屏幕截图，或者从终端发送。每条消息都会由一个人阅读，并且回复将发送到您的帐户电子邮件中。

在 MIOSA 中，`miosa feedback "miosa deploy hangs after the build finishes"` 发送一个，并附加您的 CLI 版本和操作系统。

相关：CLI、组织

### 主机指纹

主机指纹是机器加密身份的标识符。 MIOSA 使用它在再次连接时识别同一台已注册的计算机。

这就是为什么可以区分一台机器和一台相似的机器，以及为什么它的名称、IP 地址或主机 ID 本身并不能识别身份。

在 MIOSA 中，当您的实验室服务器在重新启动后重新连接时，MIOSA 会通过指纹识别它是同一台已注册的主机。

相关：主机密钥、主机、OpenComputer

### 主机密钥

主机密钥是 OpenComputer 智能体用来证明其连接是您注册的计算机的秘密。当您注册主机时，它会打印一次。

立即保存，因为它无法再次显示。它与您的 API 密钥不同：主机密钥连接您服务器的智能体，并且您的 API 密钥授权要求其运行命令的请求。

在 MIOSA 中，`miosa host register studio --platform linux` 打印一次主机 ID 和主机密钥。

相关：主机指纹、OpenComputer、API 密钥

### 邀请

通过邀请，您可以将尚未加入 MIOSA 的人员添加到组织或工作区。他们收到一封带有链接的电子邮件并接受它。

使用工作区邀请将他们添加到一个工作区，或使用组织邀请首先将他们添加到整个组织。

在 MIOSA 中，`miosa org invite dana@example.com --role member` 发送 1。如果电子邮件已属于组织成员，工作区邀请会直接添加他们。

相关：成员、角色、组织、工作空间

### 会员

成员是在一个组织内被授予角色的用户。会员身份实际上授予访问权限。

用它来控制谁可以看到和更改什么。登录但尚未添加到组织的用户无法访问该组织中的任何内容。

在 MIOSA 中，您可以使用 `miosa member add` 添加成员，他们的角色（所有者、管理员、成员或查看者）决定他们可以执行的操作。只有所有者和管理员才能更改成员身份。

相关：用户、角色、组织、邀请

### 组织

组织是 MIOSA 上客户或公司的顶级边界。它拥有成员、计划、计费、域、API 密钥和策略。

你创造的一切都生活在一个人的统治下。它是计费的单位，也是将一个客户的资源与另一个客户的资源分开的墙，即使他们使用相同的段。

在 MIOSA 中，所有权链运行组织、工作空间、项目，然后是沙箱或部署。 Lumen 是一个组织；它的客户坐在它下面作为工作空间。

相关：工作空间、成员、计划、租户、用户

### 项目

项目将一个产品或应用程序的开发和生产资源分组。它位于工作区内。Use it to keep Sandboxes, Deployments, data services, and environments for one product together.每个项目都有 `production` 和 `staging` 环境。

在 MIOSA 中，Lumen 的“Lead Magnet”是一个项目，其中包含用于构建它的沙箱以及为其提供服务的部署。如果未给出项目，则使用 `default` 项目。

相关：工作区、沙箱、部署、external_project_id、服务、项目画布、预览环境

### 角色

角色是授予成员的一组命名权限：所有者、管理员、成员或查看者。

Use the least powerful role that does the job.浏览者阅读，成员创建和管理资源，管理员管理成员和资源，所有者也可以转让和删除。

在 MIOSA 中，Northwind Agency 设计师是客户工作区的查看者，而客户负责人是管理员。 A Role is permanent until changed; an approval is a one-time yes.

Related: Member, Authorization, Approval

### 范围

范围是 API 密钥的一种特定权限，例如 `sandboxes:exec` 或 `deployments:write`。 A key can only do what its scopes allow.

Give each key the fewest scopes it needs.读取通常需要匹配的 `:read` 范围，写入需要 `:write`。

在 MIOSA 中，预设捆绑常见集：`read-only`、`ci`、`agent` 和 `cli`。没有正确作用域的调用会得到一个 `403` 来命名缺少的作用域。

相关：API 密钥、角色、授权、API 密钥预设

### 服务帐户

服务帐户是程序的身份，而不是人的身份。当创建 API 密钥的人离开组织时，其 API 密钥仍然有效。

将其用于 CI 管道、后端自动化以及生产中的任何内容。 Prefer it over a personal key.

在 MIOSA 中，`miosa service-account new deploy-pipeline` 创建一个，`miosa service-account key new <account> --preset ci --expires-in 90` 为其提供一个密钥。

相关：API 密钥、API 密钥预设、成员、组织

### Two-factor authentication

双因素身份验证要求在您登录的基础上提供第二个证明，即通过电子邮件发送给您的 6 位代码。

为您自己的帐户启用它，组织所有者可以要求每个成员都使用它。没有它的成员会被要求在继续之前将其打开。

在 MIOSA 中，您可以从帐户安全设置中将其打开。

相关：身份验证、组织、成员、角色

### 用户

用户是登录 MIOSA 的一个人或服务身份。 It is who you are, not what you own.

用户通过邀请或角色成为组织成员即可获得访问权限。 One person can belong to several Organizations.

Be precise with "account".使用**用户**作为登录身份，使用**组织**作为拥有资源和计费的客户边界。 In MIOSA, Alice at Acme Corp is a User; Acme Corp is the Organization.

相关：成员、组织、角色、身份验证

### 工作区

工作区是组织内一个团队、客户或业务线的隔离区域。它拥有项目以及在其边界内创建的所有内容。

使用工作区来分隔客户、拆分账单并为团队提供自己的空间。在您转售的平台中，您的每位客户通常都是一个工作区。

在 MIOSA 中，Northwind 智能体组织为每个客户创建一个工作区。然后，资源、使用情况和 App Engine 主机将按客户端分开。

相关：组织、项目、external_workspace_id、App Engine 主机、Slug

## 智能体

AI 智能体、利用、运行以及它们发出的事件。

### 智能体

智能体是人工智能工作人员保存的、版本化的配方：哪个运行框架运行它、哪个模型、它的指令、它使用哪台机器以及允许它做什么。

使用保存的智能体来完成您重复的工作，例如审查每个拉取请求。您可以通过名称或 ID 引用它，并在沙箱或计算机上运行它。智能体使用您自己的模型连接，而不是 MIOSA 平台密钥。

在 MIOSA 中，Lumen 团队会保存一次 `reviewer` 智能体，并在 PR 打开时运行 `miosa agent run reviewer "review PR 42"`。 App Engine 是托管目标，而不是智能体设备。

相关：运行框架、智能体运行、运行时配置文件、OSA、批准、计算机使用、最佳、Agent Studio、工作流程

### 智能体运行

智能体运行是针对您选择的机器跟踪 AI 智能体的执行。你用简单的语言给它一个任务，它就会起作用，并且你会得到所发生事件的稳定记录。

当任务是“为我执行此操作”而不是“运行这个确切的命令”时使用它。智能体决定步骤； plain Exec 运行您已经知道的命令。

在 MIOSA 中，Lumen 产品将“更新登陆页面并保持预览运行”发送到沙箱，并在其自己的 UI 中显示运行的输出和状态。

相关：智能体、智能体运行组、作业、批准、运行时配置文件

### 智能体运行组

智能体运行组捆绑了许多相关的智能体运行，因此您可以将它们作为一项操作进行管理。当单个请求扇出到多台机器时，请使用一个。

它跟踪计数，流式传输每个子项的事件，强制执行并发限制，并允许您立即取消整个组。

在 MIOSA 中，Northwind Agency 请求“检查 100 个客户端页面”成为一组，一次最多运行 25 个。

相关：智能体运行

### 特工工作室

Agent Studio 是您构建和使用自己的智能体的地方。聊天是主界面，旁边有一个工作区面板。

每次聊天都会获得一个温暖的沙箱，后续聊天者会重复使用它。暂停的沙箱会被其文件唤醒；只有损坏的才会被替换，聊天中也是这么说的。

在 MIOSA 中，还可以选择 Agent Studio 中保存的智能体作为最佳聊天的大脑。

相关：特工、大脑、沙盒、运行框架

### 人工智能网关

AI 网关位于您的应用程序和模型提供商之间。路由策略规定哪个模型服务哪个请求以及回退到哪个模型；预算并限制支出上限和费率。

使用它可以在不更改应用程序代码的情况下切换模型，并查看每个请求的跟踪。

在MIOSA中，在控制台中打开**AI Gateway**，或使用`miosa gateway policy list`和`miosa gateway requests --limit 20`。

相关：连接、速率限制、支出上限、智能体

### 批准

批准是一个人在继续执行受限步骤（例如部署或外部写入）之前给出的一次性“是”。

用它来让人们了解危险行为。这不是永久许可：它涵盖了所询问的步骤。

在 MIOSA 中，`miosa agent approvals list` 显示等待的请求，`miosa agent approvals approve` 让暂停的运行继续。计算机使用协议中的批准门控是一种客户端约定，因此也可以在您自己的代码中设置敏感步骤。

相关：智能体运行、角色、授权

### 大脑

大脑是在最佳聊天中完成工作的模型或智能体。您可以在第一条消息之前选择它。

- **最佳**：MIOSA 自己的模型，通过钱包积分支付
- **Aharness**：Claude Code、Codex、OSA 或其他harness，使用您自己的帐户在计算机上运行
- **已保存的智能体**：您在 Agent Studio 中构建的智能体

在 MIOSA 中，大脑在收到第一条消息后就被锁定；开始一个新的聊天来更改它。

相关：最佳聊天、最佳、Harness、Agent Studio

### 电脑使用

计算机的使用是一个循环，软件查看屏幕、做出决定、采取一个操作，然后再次查看：屏幕截图、单击、键入、滚动。它让人工智能操作真正的桌面。

当任务依赖于像素时使用它：登录的浏览器、桌面应用程序或人工接管自动化停止的地方。对于代码和构建，请使用沙箱。

在 MIOSA 中，循环通过 SDK、MCP 工具、REST API 或实时查看器针对计算机运行。您自带智能体人；没有托管循环。

相关：计算机、桌面会话、智能体、MCP

### 连接

连接是 MIOSA 为您保留的另一项服务上的帐户或密钥，因此智能体和工作流程可以使用它，而无需您将机密粘贴到其中。

共有三种：**模型提供商**（Claude 或 ChatGPT 登录、提供商 API 密钥）、**应用程序**（GitHub、Google、Slack 等，通常通过 OAuth）和**工具服务器**。对于 OAuth 应用程序，MIOSA 在后台刷新令牌。

在 MIOSA 中，在控制台中的 **连接** 下或使用 `miosa connections` 管理它们。

相关：工具服务器、秘密、智能体、Harness

### 事件流（SSE）

事件流使一个连接保持打开状态，并使用服务器发送的事件 (SSE) 在发生更新时向您推送更新。命令输出和最终结果逐行到达，而不是全部到达最后。使用它来实时显示进度，例如构建日志或终端。它是一个开放请求，与 Webhook 不同，MIOSA 稍后将其作为单独的调用发送到您的服务器。

在 MIOSA 中，流式执行以退出事件结束，并且 `miosa events my-box` 流式传输沙箱的状态更改。

相关：Webhook、Exec、日志

### 证据

证据是记录的结果，证明操作确实达到了您需要的状态。这是您可以核实的事实，而不是承诺。

使用它而不是信任“已接受”或“已排队​​”。请求被接受仅证明 MIOSA 已收到该请求。

在 MIOSA 中，发布以路由、运行时和公共 URL 有效的证据结束。对于已连接的主机，新的心跳加上已完成的命令就是证据。

相关：准备情况、智能体运行

### 运行框架

运行框架是在运行中实际完成工作的智能体程序：`claude-code`、`codex` 或 `osa`。 MIOSA提供机器；运行框架提供了思维和工具的使用。

每个智能体或每次运行选择一个。单独的`--model`选择它使用的模型，如果不说，运行框架默认为`claude-code`。

在 MIOSA 中，`miosa prompt --new-machine --harness codex "write a README"` 提供一台机器并让 Codex 在那里编写 README。

相关：智能体、智能体运行、OSA、MCP

### MCP

MCP（模型上下文协议）是 AI 应用程序发现和使用工具的标准方式。 MIOSA 运行 MCP 服务器，因此兼容的客户端可以创建沙箱、运行命令并通过调用工具进行部署。

当您希望 Claude Code、Cursor 或 OSA 等助手使用与 CLI 相同的 API 密钥直接操作 MIOSA 时，请使用它。

在 MIOSA 中，`miosa mcp install --client claude` 将服务器添加到 Claude Code 的配置中。 MIOSA REST API 是独立的； MCP 是其之上的工具层。

相关：OSA、Harness、智能体、工具服务器

### 内存

内存是工作空间的知识存储。最佳搜索它来回答问题并引用它所使用的内容。

在聊天中询问 Optimal 保存注释，或从终端导入 Notion 导出。内存在工作区中作为一台永远在线的机器运行，并且像一台机器一样计费，因此您可以有意启动它。

在 MIOSA 中，从 **Optimal** 打开它，然后从 **Memory** 打开它，以搜索工作区知道的内容。

相关：最佳、Optimal Engine、最佳聊天、工作空间

### 最佳

最佳方案是 MIOSA 中内置的智能体。您在聊天中描述您想要的内容，它会从您的实时工作区中进行回答，在您选择的沙箱或计算机上构建，或者调查问题。

它仅在您的组织和工作区内部有效，具有您的权限，并且更改工作区的步骤需要等待您的批准，除非您允许。

在 MIOSA 中，从控制台侧边栏中的 **Optimal** 打开它，或从终端使用 `miosa optimal chat "how many sandboxes are running?"`。

相关：最佳聊天、大脑、批准、记忆、智能体

### 最佳聊天

最佳聊天是与最佳的一次对话。每个聊天都采用以下三种模式之一：

- **从实时工作空间环境中询问**答案，无需接触机器
- **构建** 在沙箱或计算机上构建或更改某些内容
- **调查**在得出结论之前追踪证据

聊天属于其开始所在的工作区，并且永远不会移动。在您与工作区共享之前，聊天都是私人的。

在 MIOSA 中，`miosa optimal chats` 列出您的聊天记录，最新的在前。

相关：最佳、大脑、认可、记忆

### Optimal Engine

Optimal Engine存储和搜索智能体的知识：按工作空间组织的注释、文档和决策。

在 MIOSA 上，托管引擎就像带有引擎 `optimal` 的托管数据库一样运行，并具有备份和升级功能。您还可以自己运行一个并保持本地引擎和云引擎之间的工作空间同步。

在 MIOSA 中，`miosa engine create` 创建一个托管引擎，并且 `miosa engine attach` 将工作区连接到它。

相关：内存、最佳、托管数据库、备份

### OSA

OSA 是 MIOSA 的开源智能体。它安装在您的计算机上，与您自己的 Claude 或 ChatGPT 订阅一起使用，并充当 MCP 客户端，因此 MIOSA 的工具显示在其内置工具旁边。

当您想要一个已经知道如何从您的终端或计算机上使用 MIOSA 的智能体时，请使用它。计算机出厂时已安装 OSA，但在您激活它之前处于禁用状态。在 MIOSA 中，`miosa prompt --harness osa --new-machine "summarize this repository"` 在新机器上运行它。

相关：运行框架、MCP、智能体、计算机、最优

### 运行时配置文件

运行时配置文件是一组可重用的默认值，用于说明智能体运行时的准备方式：它获取哪个运行器、工具、连接器、环境和策略。

使用一个这样您就不会在每次运行时重复相同的设置。配置文件决定了运行时间；每个智能体运行仍然提供提示、目标和超时。

在 MIOSA 中，Lumen 为沙箱和计算机创建了 `lumen-claude` 配置文件，然后在多次运行中引用它。

不要与沙盒创建中的 `runtime_profile` 字段混淆，该字段选择 VM 引擎。请参阅[runtime_profile](/docs/glossary#runtime-profile-field)。

相关：Agent Run、Agent、runtime_profile（沙箱字段）

### 工具服务器

工具服务器通过 MCP 从另一个服务向智能体提供额外的工具。 MIOSA 保留了官方目录，包括 GitHub、Linear、Notion、Sentry 和 Stripe。

添加一个会要求供应商准确提供所需的密钥，在保存之前测试密钥，并将其保存在工作区保管库中。

在 MIOSA 中，打开 **连接**，然后打开 **工具服务器**，然后打开 **浏览目录**。

相关：连接、MCP、智能体

### 网络钩子

Webhook 是 MIOSA 在发生某些情况（例如沙箱准备就绪或部署成功）时发送到您自己的服务器的消息。你不必一直问。

使用它来更新数据库、通知用户或开始下一步。每件货物都有签名，因此您可以检查它是否确实来自 MIOSA。

在 MIOSA 中，Lumen 注册 `https://example.com/hooks/miosa`，验证原始正文的 HMAC-SHA256 签名，并使用事件 `id` 忽略重复项。

相关：事件流（SSE）、HMAC签名

### 工作流程

工作流将步骤链接在一起，例如智能体运行后调用工具，因此重复的流程每次都以相同的方式运行。

手动或通过触发器启动运行，在需要休息时暂停触发器，并读取每次运行的状态。

在 MIOSA 中，`miosa workflow run <workflow> --input '{"branch":"main"}'` 开始运行，`miosa workflow runs` 列出最近的运行。

相关：智能体、智能体运行、Cron 作业、工具服务器

## 网络和域

主机名、DNS、证书和路由。

### 顶级域

Apex 域是没有前缀的裸域：`example.net`，而不是 `www.example.net` 或 `app.example.net`。它位于域的根部。

这很重要，因为根目录不允许使用通常的 CNAME 记录，因此您可以使用 A/AAAA 或提供商的 ALIAS、ANAME 或扁平 CNAME。

在 MIOSA 中，如果您的 DNS 提供商（例如 GoDaddy）不支持扁平化，则顶级域需要解决方法。像 `app.example.net` 这样的子域更简单。

相关：自定义域名、DNS记录、DNS验证

### 自定义域

自定义域是您或您的客户拥有的一个主机名，例如 `portal.example.net`，直接附加到单个部署。

当客户希望在他们的应用程序上拥有自己的地址时，请使用它。您附加它，添加 MIOSA 向您显示的 DNS 记录，并要求 MIOSA 验证它。 MIOSA 然后颁发 HTTPS 证书。

在MIOSA中，`miosa deploy domain-add team-portal portal.example.net`注册它并打印要添加的记录。

相关：部署域、DNS 验证、TLS 证书、部署、DNS 记录、Apex 域

### 部署域

部署域是您的组织控制的父域，用于为每个生产应用程序提供稳定的地址，例如 `lead-magnet.apps.example.com`。

当您生成许多应用程序并希望它们全部位于一个品牌域下时，请使用它。它与自定义域不同，自定义域将一个特定的客户拥有的主机名附加到一个部署。

在 MIOSA 中，如果未设置部署域，应用程序将使用托管后备 `{slug}.{organization}.miosa.app`。按照[部署域](/docs/docker-host/domains)选择正确的设置。

相关：自定义域、预览域、部署、平台 URL

### DNS记录

DNS 记录是域设置中的一个条目，它告诉 Internet 名称的通向方向。常见的是CNAME（指向另一个名称）和A（指向IP地址）。

当您附加自定义域时，MIOSA 会显示要在 DNS 提供商处添加的确切记录。添加它，然后验证。在 MIOSA 中，`portal.example.net` 对验证目标使用 CNAME。像 `example.net` 这样的裸域需要 A/AAAA、ALIAS、ANAME 或扁平 CNAME，具体取决于您的提供商。

相关：自定义域、DNS 验证、Apex 域、TLS 证书

### DNS验证

DNS 验证是验证您的主机名点的 DNS 记录是否符合 MIOSA 要求的检查。

在附加自定义域后执行此操作。在通过之前，MIOSA 不会路由流量或为该名称颁发证书。

在 MIOSA 中，您添加 `miosa deploy domains` 显示的 CNAME 或 A 记录，然后运行 ​​`miosa deploy domain-verify`。 DNS 更改可能需要一段时间才能传播，因此如果失败请立即重试。

相关：自定义域、TLS 证书、路由、DNS 记录

### 域名

域是一个主机名，如 `portal.example.net`，它将访问者发送到 MIOSA 上的某些内容：预览、部署、计算机或其他资源。

使用域名，以便人们通过您可以阅读和记住的地址访问您的应用程序。域路由到部署，部署为其活动版本提供服务，因此当代码更改时地址保持不变。

在 MIOSA 中，Lumen 的应用程序在 `lead-magnet.apps.example.com` 和 Acme Corp 的 `portal.example.net` 上进行应答。始终显示 API 返回的 `public_url`，而不是自己构建主机名。

相关：部署、自定义域、部署域、路由

### 出口

出口意味着出站流量：沙盒或计算机对其他服务（例如 AI 提供商、GitHub 或包注册表）进行的调用。

观察它，了解你的工作量真正接触到的是什么，然后限制它。这限制了代码，尤其是人工智能编写的代码所能达到的范围。

在 MIOSA 中，新沙箱以仅审核模式启动，记录每个出站呼叫并且不阻止任何呼叫。准备好后，锁定白名单； `miosa egress allowlist` 显示允许的主机。

相关：网络策略、秘密、隔离、沙箱

### 网络政策

网络策略限制机器可以联系的外部地址。它是围绕工作负载可以达到的范围的栅栏。

使用它来包含不受信任的代码或阻止 AI 智能体发出意外的出站呼叫。它限制了交通的去向；它不会登录到目的地。

在 MIOSA 中，新沙盒以仅审核模式启动，记录每个出站呼叫，您可以稍后锁定到允许名单。计算机在端口 443 上使用 `allowlist` 策略和 `github.com` 等规则。

相关：隔离、沙箱、出口

### 平台网址

平台 URL 是 MIOSA 提供的立即可用的地址，无需您进行 DNS 设置。

使用它来测试、共享快速链接，或者在您设置品牌域时作为始终可用的后备。

在 MIOSA 中，部署获得托管回退，例如 `https://team-portal.example-org.miosa.app`。预览版还获得以 `.sandbox.miosa.ai` 结尾的平台主机名。

相关：自定义域、部署域、预览、公共地址

### 端口转发

端口转发使沙箱内的服务（例如数据库或调试器）出现在您自己计算机的端口上。

将其用于非网页的任何内容，或者当您不需要公共 URL 时。对于要共享的 HTTP 端口，请创建预览。

在 MIOSA 中，`miosa proxy my-box 5432:5432` 将本地端口 5432 转发到沙箱的端口 5432，直到您按 Ctrl-C。

相关：预览、沙盒、隧道、范围

### 预览域

预览域是用于构建临时沙盒预览地址的品牌父域。它决定预览的地址是什么样的。

当您以自己的品牌转售 MIOSA 并希望在您的域而不是 MIOSA 上预览时，请使用它。它与生产应用程序的域是分开的，因此如果您想要两者都品牌化，则将两者都品牌化。

例如，一家名为 Lumen 的虚构公司拥有 `example.com`，可以在 `https://5173-abc123.sandbox.example.com` 上看到其预览。 Lumen 和 `example.com` 是示例，不是真实的。 DNS 是一个通配符 `CNAME`、`*`，指向 `proxy.miosa.ai`。

相关：预览、部署域、平台 URL

### 私人地址

私有地址是一个服务用于在不通过互联网的情况下到达另一个服务的内部名称。MIOSA 上服务之间的专用网络尚不可用：API 的 `private_network` 读取 `{"enabled": false}`，旧的 `private_domain` (`<slug>.miosa.internal`) 和 `MIOSA_PRIVATE_DOMAIN` 无法解析。通过其公共地址呼叫另一个服务。

托管数据库自动连接：在变量中引用 `${{Postgres.DATABASE_URL}}` 或 `${{Redis.REDIS_URL}}`。

相关：服务、私人服务、公共广播、网络政策

### 公共广播

公共地址是网络服务或静态站点的互联网地址。它以 `miosa.app` 结尾，MIOSA 颁发并续订其 TLS 证书。

当可以通过互联网访问该服务时将其打开；将其关闭，该服务将仅在其私有地址上运行。对于您自己的域，添加自定义域。

在 MIOSA 中，`miosa service domains enable shop API --label api` 提供服务 `https://api.<your-org>.miosa.app`。

相关：服务、私有地址、自定义域、平台 URL、TLS 证书

### 路由

路由是 MIOSA 决定请求去向的方式：从主机名到正确的组织、部署和活动版本。

这就是为什么更改活动版本或回滚无需触及 DNS 即可生效。地址保留；它后面的路线移动。

在 MIOSA 中，对 `portal.example.net` 的请求被路由到 Lumen 的 `team-portal` 部署并从其活动版本提供服务。默认情况下，边缘路由器会在 60 秒内刷新其路由缓存。

相关：域、部署、DNS 验证

### 沙盒分享

沙盒共享是一个链接，可让某人在没有帐户的情况下观看正在运行的沙盒。他们只能看，不能开车。

用它向队友或客户展示智能体正在做什么。撤销共享，链接立即停止工作。

在 MIOSA 中，共享 URL 类似于 `https://{sandbox-id}.sandboxes.miosa.ai?ms=ms_<token>`，并且可以在创建时指定过期时间。

相关：共享代币、预览、沙箱

### 分享代币

共享令牌是一种短暂的、有范围的凭证，可让特定浏览器打开私有预览，而不会暴露您的 API 密钥。

使用它在您的产品中嵌入预览或发送限时链接。它会被退回一次，因此请保存它或铸造一个新的。

在 MIOSA 中，`miosa preview share my-box <id> --ttl 1h` 生成一个有效期为一小时的链接。智能体在请求到达您的应用程序之前剥离令牌。

相关：预览、浏览器令牌、API 密钥

### TLS 证书

TLS 证书（通常称为 SSL）使挂锁和 `https://` 对主机名起作用。它对流量进行加密，并显示该网站确实是其声称的网站。

您无需购买或安装。 MIOSA 会在验证您的主机名的 DNS 后自动发出它。

在 MIOSA 中，一旦 `portal.example.net` 验证，HTTPS 就开始工作。该证书并不能证明您拥有域名注册； DNS 验证可以。

相关：DNS 验证、自定义域

### 隧道

隧道在 MIOSA 管理的地址处发布已连接主机的一个端口。 MIOSA 将请求沿着主机的出站连接路由回您的服务。

使用它可以访问防火墙后面的计算机上的某些内容，例如实验室计算机上的开发服务器。连接主机不会暴露任何内容；隧道是一个单独的、显式的暴露，具有自己的访问策略。

在 MIOSA 中，`miosa host tunnel new <host> --port 3000 --slug my-app-dev --access organization` 创建您的组织可访问的一个。

相关：OpenComputer、预览版、主机

## 数据

配置、秘密和持久存储。

### 备份

备份是在某个时间点获取的数据库的保存副本，因此您可以在出现错误或故障后恢复它。

在危险的变化之前采取一项措施。请记住，回滚 Deployment 不会回滚您的数据；而是会回滚您的数据。恢复即可。

在 MIOSA 中，`miosa db backup <database>` 现在取 1，`miosa db backups <database>` 列出它们。备份存储在数据库运行时之外。

相关：托管数据库、Postgres、快照、回滚

### 绑定

绑定是应用程序与其依赖的事物之间的持久链接：数据库、卷、秘密、存储桶或服务。

使用绑定，以便应用程序获取每个环境的正确连接详细信息，而无需将数据复制到应用程序中。数据有自己的生命周期，与部署分开。在 MIOSA 中，您将 Postgres 附加到项目，并在启动时注入 `DATABASE_URL`。登台获取登台数据库，生产获取生产数据库，具有相同的变量名称。

相关：部署、托管数据库、卷、秘密、对象存储、连接字符串

### 桶

Bucket 是对象存储中的命名容器。您可以通过键将文件放入其中，例如 `uploads/foo.png`，然后再将它们取回。

使用一个用于用户上传和生成的资产，与应用程序的代码和数据库分开。

在 MIOSA 中，每个项目的存储桶都是通过 S3 兼容的 API 访问的，并且 `STORAGE_BUCKET` 被注入到您的应用程序中。

相关：对象存储、预签名 URL、绑定

### 连接字符串

连接字符串是一行，如 `postgresql://user:pass@host:port/db`，它包含连接到数据库所需的地址、名称和凭据。

将其视为密码。您的应用程序从环境变量中读取它，通常是 `DATABASE_URL`，因此您永远不会对其进行硬编码。

在 MIOSA 中，您将数据库附加到环境，MIOSA 在启动时注入正确的连接字符串。 `miosa db connection <database>` 打印它。

相关：托管数据库、绑定、秘密、环境变量

### 数据驻留

数据驻留是在整个工作流程中存储和处理数据的地方：文件、输出、工件以及发送到 AI 模型的任何请求。

当规则或客户要求数据保留在某个位置时，请检查它。在您自己的计算机上运行命令本身并不会将结果或模型请求保留在那里。

在 MIOSA 中，资源位于一个区域，例如 `us-west`，数据服务位于该区域。对于 OpenComputers，请查看[数据边界](/docs/opencomputers/security#data-boundaries)。

相关：数据平面、本地、OpenComputers

### 环境变量

环境变量是程序启动时传递给程序的命名设置，例如 `DATABASE_URL` 或 `API_BASE_URL`。它将配置保留在您的代码之外。

将它们用于不同地点的不同值：登台与生产，或者一个客户与另一个客户。名称必须大写，例如 `NEXT_PUBLIC_API_URL`。

在 MIOSA 中，一个值可以来自多个层。当名称冲突时，更具体的层获胜：组织，然后是工作区、项目、资源本身，最后是单个运行。

相关：秘密、环境、绑定、连接字符串、共享变量、变量引用

### 原木排水

日志排出将您的日志发送到您选择的位置，例如您的日志记录服务。

使用它可以将日志保留更长时间，使用您自己的工具搜索它们，或者对它们发出警报。漏电可以是 HTTPS，每行一个 JSON 对象和一个签名密钥，也可以是基于 TLS 的系统日志。

在 MIOSA 中，`miosa drains add --name ops --url https://logs.example.test/ingest` 创建一个，`miosa drains test ops` 发送一个带符号的行来检查它。

相关：日志、服务、Webhook

### 托管数据库

托管数据库是 MIOSA 为您创建、运行、备份和连接的数据库。您选择引擎； MIOSA 负责处理服务器。

当您的应用程序需要记住用户、订单、搜索等内容时，请使用其中之一。它与您的计算分开，因此替换沙箱或发布新版本不会将其删除。

在 MIOSA 中，您可以创建 Postgres、MySQL、Redis 或 Qdrant。 `miosa db list` 显示它们，并且它们的连接字符串作为环境变量传递给您的应用程序。

相关：绑定、卷、对象存储、Postgres、Redis、矢量数据库、备份、连接字符串

### 对象存储

对象存储将文件保存在存储桶中，并按名称将它们传回：图像、上传、导出、生成的资产。它是为许多文件和大文件而构建的。

将其用于用户上传或智能体生成的任何内容，这些内容应比任何一台计算机的寿命都长。它不是您挂载的文件系统；您可以通过 S3 兼容的 API 或签名链接来访问它。

在 MIOSA 中，每个项目都会获得一个包含 `STORAGE_BUCKET`、`STORAGE_ENDPOINT` 和注入的关键变量的存储桶，并且标准 S3 库可以正常工作。

相关：卷、绑定、托管数据库、存储桶、预签名 URL

### Postgres

Postgres 是一个关系数据库，用于存储包含表、联接和事务的结构化数据。 MIOSA 可以为您每个项目运行它。为用户、订单和您查询的任何内容选择它。它与您的计算分开运行，因此替换沙箱或发布新版本不会将其删除。

在 MIOSA 中，使用 `miosa api POST /databases` 创建一个并在运行时读取 `DATABASE_URL`。 `miosa db backup <database>` 进行按需备份。

相关：托管数据库、连接字符串、备份、绑定

### 预签名 URL

预签名 URL 是一种由 MIOSA 签名的临时链接，允许一次上传或下载一个文件，而无需 API 密钥。

使用它可以让浏览器将大文件直接发送到存储，跳过服务器。超过 5 MB 的大型直接上传应使用此路径。

在 MIOSA 中，`POST /storage/buckets/{id}/presign` 与 `key` 和 `method` 返回 1。

相关：存储桶、对象存储、共享代币

### Redis

Redis 是一种非常快速的键值存储，可将数据保存在内存中。它通常用于缓存、会话、速率限制和发布/订阅。

使用它可以使您的应用程序更快或保存短暂的数据。将其视为缓存类，而不是最重要记录的所在地；使用 Postgres 来解决这些问题。

在 MIOSA 中，每个项目都会创建一个托管 Redis 实例，并以 `REDIS_URL` 的形式向您的应用程序公开。它是单节点的。

相关：托管数据库、连接字符串、绑定、Postgres

### 秘密

Secret 是一个敏感值，例如支付或 AI 提供商密钥，由 MIOSA 存储并受到保护，并且对明文的访问受到限制和审核。

使用它而不是简单的配置来处理任何如果泄露就会有害的事情。秘密作为不透明的占位符绑定到机器上，因此您真正的密钥永远不会存在于机器内。

在 MIOSA 中，智能体的代码读取 `OPENAI_API_KEY` 并获取占位符；真正的密钥仅在出站呼叫时交换。您将其旋转到一个地方，然后每台机器都会收到变化。

相关：环境变量、绑定、API 密钥

### 共享变量

共享变量在环境中设置一次，该环境中的每个服务都可以读取它，例如多个服务使用的 API 基本 URL。

使用它而不是将相同的值复制到每个服务中。服务通过引用读取它，并且更改它会将读取它的每个服务标记为需要重新部署。

在 MIOSA 中，`miosa project vars set shop API_BASE=https://api.acme.dev` 设置为 1，服务将其读取为 `${{shared.API_BASE}}`。

相关：变量引用、环境变量、服务、环境

### 变量引用

变量引用指向一个值而不是复制它。 MIOSA 在发布开始时解决它，因此服务始终获取当前值。

- `${{Postgres.DATABASE_URL}}`：同一环境中另一个服务的变量
- `${{shared.API_BASE}}`：共享变量
- `${{NAME}}`：同一服务的另一个变量
- `${{secret(32)}}`：生成的 32 个字符的随机秘密

在 MIOSA 中，`miosa service vars effective shop API` 显示每个已解析的变量（仍被屏蔽）以及任何会阻止部署的问题。

相关：共享变量、环境变量、秘密、服务

### 向量数据库

Vector 数据库存储嵌入，即捕获含义的数字列表，并查找最接近的匹配项。这就是相似性搜索的工作原理。

将其用于检索增强生成 (RAG)、文档搜索、推荐和长期智能体记忆。

在 MIOSA 中，托管 Qdrant 为每个项目提供一个注入了 `QDRANT_URL` 的专用向量数据库。将原始文件保存在对象存储中，将向量保存在 Qdrant 中。

相关：托管数据库、对象存储、连接字符串

### 音量

卷是可以附加到计算机的永久磁盘。即使计算机重新启动或被更换，它也会保留您写入的内容。

将它用于必须在文件系统上生存和存在的事物：本地 SQLite 数据库、不能丢失的缓存或下载一次的大型模型权重。对于真正的数据库，请使用 Postgres，对于用户上传，请使用对象存储。

在 MIOSA 中，`miosa volume create model-weights --size-gb 50` 生成 50 GB 卷。卷位于一台主机上，因此它们不会自动跨主机移动。

相关：绑定、对象存储、发布

## 计费和使用

信用、计量、限制和计划。

### 自动重新加载

当您的余额低于您选择的金额时，自动充值会从您的卡中增加积分，但永远不会超过每月的最高限额。组织的所有者或计费经理在“计费”中的“预算和限制”下将其打开：安全结账立即添加首次充值，并在您批准这些费用后保存卡。

关闭自动重新加载或拒绝收费后，余额 0 美元将暂停运行沙箱和计算机，直到您添加积分、数据库和部署停止。什么都没有被删除。

相关：信用、钱包、信用包、支出上限

### 信用

信用是 MIOSA 衡量和计费使用情况的单位。一个信用相当于一美分。运行机器、存储、构建和人工智能调用都会从您的钱包余额中提取积分。

积分来自您的计划每月包含的使用量以及您添加的积分包。您添加的积分永不过期；每月计划积分在授予后一个月到期。

在MIOSA中，`miosa billing balance`显示您的余额，`miosa limits`显示下一台机器将向哪个钱包计费以及是否可以启动。

相关：使用情况、计划、支出上限、钱包、自动充值、信用包、包含的使用情况

### 信用包

积分包是您在一次付款中添加到钱包中的一组积分。

当您想要的金额超出您的计划所包含的金额时，请添加积分，或者让免费帐户的运行金额超过 1 美元。您添加的积分永远不会过期。在免费模式下，任何超过 0 美元的附加余额都会将您的限额提高到“免费并添加积分”。

在 MIOSA 中，从控制台中的 **Billing** 添加积分。提供的套餐价格为 5 美元、25 美元、50 美元和 100 美元。

相关：信用、自动充值、钱包、包含使用

### 包含的用法

包含的使用量是您的计划每月为您提供的使用量。付费计划的价格随着使用情况而变化：商业版的价格是每月 500 美元，使用量为 500 美元，按公布的价格消费。

免费包括每月 1 美元的使用费，除非您添加积分，否则就停止使用。付费计划持续超过所包含的金额，即用即付。

在 MIOSA 中，经常性计划积分在授予后一个月到期；您添加的积分永远不会过期。

相关：计划、信用、信用包、自动重新加载

### 计划

计划是您组织的订阅级别。有四种：免费（0 美元，每月使用费 1 美元）、开发者（每月 20 美元）、商业（每月 500 美元）和企业（每月 2,000 美元）。付费计划的价格以相同的使用量计算。

每个计划为尺寸支付相同的价格。计划的不同之处在于包含的使用情况以及可以运行的数量：副本、大小以及同时运行多少个沙箱、计算机、数据库和项目。

在 MIOSA 中，`miosa billing plan` 显示您的计划和使用情况及其限制。在控制台的**账单**中更改计划。

相关：组织、信用、配额、包含的用途、信用包

### 价格手册

价格手册是 MIOSA 收费的费率列表：每小时和每月的每种大小、磁盘、出口、构建、快照和模型代币。

每个价格手册都有一个版本和生效日期，因此您可以知道何时应用哪些价格。计划永远不会改变尺寸的价格，只会改变限制。

在 MIOSA 中，`GET /api/v1/pricing` 返回当前价格手册；定价页面是根据它构建的。

相关：计划、信用、使用情况

### 配额

配额是您对可以使用的东西的数量设置的限制：多少个沙箱、一次多少个、多少存储空间或多少支出。

用它来阻止一个用户使用所有东西。配额是上限；使用量是当前的计数。

在 MIOSA 中，Lumen 平台将每个最终用户的上限限制为 3 个并发沙箱。创建沙箱时会检查配额，因此它们不会影响已经运行的沙箱。

相关：使用情况、支出上限、计划、速率限制

### 速率限制

速率限制限制了您调用 API 的速度。仔细查看它，您会得到一个 HTTP `429`，其中有一个 `Retry-After` 标头，告诉您要等待多长时间。

暂时退出并重试。不要在紧密循环中重试。读取 `X-RateLimit-*` 标头而不是硬编码数字。

在 MIOSA 中，记录的限制为每个工作区每分钟 600 个请求，每个端点组每分钟 60 个请求，并且这些限制可能因密钥和策略而异。联系支持人员以筹集资金以进行大规模集成。

相关：配额、API 密钥、计划

### 支出上限

支出上限限制了一个月内可以支出的金额。在组织、工作区或一名成员上设置一项。

当达到上限时，它会暂停，因此新的支出会被拒绝，正在运行的工作负载会停止但不会被销毁，或者它只会发出警报。默认情况下，通过电子邮件和 Webhook 发出警报的频率为 50%、80%、90% 和 100%。暂停后没有任何事情会自行恢复。

在 MIOSA 中，`miosa billing cap show` 列出了上限，`miosa org caps set dana --spend 25` 限制一名成员每月 25 美元。

相关：配额、信用、使用情况、自动充值、钱包

### 用法

使用情况是您消耗的测量资源量，归因于组织、工作区或资源：计算秒数、存储、带宽。

用它来查看积分的去向，如果您转售 MIOSA，还可以向您自己的客户开具账单。使用情况不是发票；它是基础测量。

在 MIOSA 中，`miosa usage my-box` 显示沙箱的运行时间、剩余时间和估计成本。平台构建者按`external_workspace_id`对使用情况进行分组，以向每个客户收费。

相关：信用、配额、external_workspace_id、钱包、包含的使用情况

### 钱包

钱包是您使用的资金的来源：信用余额和（可选）一张卡。

每个人都有一个个人钱包，每个组织都有一个。即使您稍后切换组织，机器也会对创建它的钱包进行计费。

在 MIOSA 中，`miosa org` 显示现在谁为新机器付费，`miosa org bill acme` 使新机器向 acme 组织计费。

相关：信用、自动重新加载、信用包、组织

## 平台建设者

在 MIOSA 之上构建产品的词语。

### API

MIOSA API 是一个 REST 接口：您的代码发送 HTTPS 请求，MIOSA 创建、更改或报告资源。

控制台和 CLI 中的所有内容都是基于它构建的。当您想从自己的后端完全控制时直接使用它。

在MIOSA中，基本URL是`https://api.miosa.ai/api/v1`，每个请求都携带`Authorization: Bearer <token>`。 SDK 和 CLI 是更友好的包装器。

相关：CLI、SDK、API 密钥、幂等性密钥、速率限制

### 浏览器令牌

浏览器令牌是您的服务器创建的一种短期凭证，以便客户的浏览器可以访问一个 MIOSA 资源，例如预览版或终端。

使用它，这样您的真实 API 密钥就永远不会到达浏览器。令牌过期、无法续订、绑定到单个资源，并且无法创建新资源。

在 MIOSA 中，Lumen 的后端为沙盒预览创建一个令牌，并仅将其通过 iframe URL 传递给客户的浏览器。

相关：API 密钥、白标签、预览

### 命令行界面

CLI 是 `miosa` 命令行程序。您可以键入命令来创建沙箱、运行代码、发布应用程序以及管理您的帐户。

使用它来快速工作和编写脚本。它以远程命令的退出代码退出，因此它可以在 CI 中工作。

在 MIOSA 中，使用 `npm i -g @miosa/cli` 安装，然后使用 `miosa login` 登录。

相关：SDK、API、API 密钥、MCP

### 外部项目 ID

`external_project_id` 是您自己的数据库中的项目或应用程序 ID。 MIOSA 将其存储为不透明字符串，将其接受为列表过滤器，并将其复制到使用、审核和子资源中。

使用它将 MIOSA 项目映射回系统中的行，无需额外查找。

在 MIOSA 中，传递不带规范 ID 或 slug 的 `external_project_id: "project_789"` 可在您的组织中解析或创建匹配的项目。

相关：项目、external_workspace_id、external_user_id

### 外部用户 ID

`external_user_id` 是您的客户帐户内的一位最终用户的 ID（您识别他们时）。 MIOSA 存储它并将其复制到使用、审计和子资源中。

使用它来强制执行每个人的限制，例如在创建另一个人之前计算一个人的活动沙箱，并提取单个客户特定的审计跟踪。

在 MIOSA 中，使用 `external_user_id: "alice"` 创建沙箱可以轻松找到 Alice 的所有工作并为其设置配额。

相关：external_workspace_id、external_project_id、配额、用户

### 外部工作空间 ID

`external_workspace_id` 是您自己系统中的客户帐户 ID。 MIOSA 将其存储为不透明字符串，并将其复制到使用、审核和子资源中，以便您稍后可以进行匹配。用它来向每个客户开具账单。当您转售 MIOSA 计算时，建议使用它来汇总使用情况。

在 MIOSA 中，在创建时传递 `external_workspace_id: "acct_123"` 将新沙箱链接到该客户。如果未给出规范 ID 或 slug，MIOSA 将解析或创建匹配的工作空间。

相关：工作空间、external_user_id、external_project_id、使用情况、租户

### HMAC 签名

HMAC 签名是使用只有您和 MIOSA 知道的秘密生成的校验和。它证明消息是真实的且未更改。

在信任 Webhook 之前请务必进行检查。计算原始请求正文的签名并进行比较。

在 MIOSA 中，`x-miosa-signature` 标头是 `sha256=` 加上 Webhook 秘密下原始正文的十六进制 HMAC-SHA256，该秘密在创建时显示一次。

相关：Webhook、秘密、API 密钥

### 幂等键

幂等性密钥是您随请求发送的唯一字符串。如果您使用相同的密钥重试，MIOSA 将返回原始结果，而不是再次执行该工作。

在每次创建时使用它，这样网络故障就不会造成重复的沙箱或双重计费。

在 MIOSA 中，发送 `Idempotency-Key: create-sandbox-for-alice-2026-05-17`。官方 SDK 在创建时会自动生成一个。

相关：API、速率限制、SDK

### 元数据

元数据是附加到 MIOSA 资源的小型自由格式注释：最多 16 个键值文本对。 MIOSA 将其存储并归还。

将其用于您自己的上下文，例如计划层、功能标志或客户标签，因此您不需要单独的表来记住哪个资源是哪个。

在 MIOSA 中，`miosa create my-box --meta team=infra` 标记沙箱，并且 Webhook 负载包含您设置的元数据。

相关：external_workspace_id、external_user_id

### SDK

SDK 是一个软件开发工具包：一个封装 API 的编程语言库。您编写 `miosa.sandboxes.create(...)` 而不是制作 HTTP 请求。

在您的后端使用一个。它处理身份验证、重试和键入错误。

在 MIOSA 中，存在适用于 TypeScript、Python、Go、Elixir、Java 和 Rust 的官方 SDK。覆盖范围因语言而异。

相关：API、CLI、API 密钥

### 蛞蝓

Slug 是出现在地址和 API 中的短小写名称，例如 `acme-corp` 或 `lead-magnet`。它比 ID 更容易读取。

对工作区和项目使用 slugs，并期望它们出现在 URL 中。一旦设置，您的组织别名就是永久性的。

在 MIOSA 中，`workspace_slug: "acme-corp"` 选择或创建工作区，部署的托管 URL 以其 slug 开头。

相关：工作空间、项目、组织、域

### 租户

“租户”是组织的一个较古老的词。您仍然会在某些 API 和文档名称中看到它，例如租户品牌、租户事件和租户预览域。

从平台构建者的角度来看，它是层次结构的顶层：您的组织拥有服务器密钥，您的客户作为工作区位于其下方。更喜欢新写作中的**组织**。

在 MIOSA 中，资源的范围属于您的组织。另一个组织无法读取或更改您的组织，即使它使用相同的 slug 或外部 ID 值。

相关：组织、工作区、白标签、external_workspace_id、预览域、Slug

### 白标

白标意味着在您自己的产品背后运行 MIOSA，这样您的客户就可以看到您的品牌和域名，而永远不会知道 MIOSA 是在下面的。

当您正在构建产品（例如 AI 应用程序构建器）并希望 MIOSA 在您拥有用户体验、定价和数据的同时提供计算时，请使用它。

在 MIOSA 中，顺序很重要：首先设置组织身份，为下游客户创建工作区和项目，分别配置预览域和部署域，然后在客户想要自己的主机名的位置附加确切的自定义域。

相关：租户、预览域、部署域、自定义域、浏览器令牌

## 运行时

引擎、主机以及工作实际运行的地方。

### 应用程序引擎

App Engine 是 MIOSA 的模型，用于在一台始终在线的主机上运行一个工作区的多个部署，每个部署都作为自己的容器。

将其用于具有许多小型应用程序、渠道、API 或客户端站点的机构和平台。 MIOSA 保留每个部署的路由、域和计费属性。在 MIOSA 中，使用 `miosa deploy create --from-sandbox my-box --name team-portal --type docker_deploy --wait` 进行发布。在主机健康之前，发布不会被标记为就绪。

相关：App Engine 主机、部署、容器、工作区、服务

### 自带云 (BYOC)

自带云 (BYOC) 意味着在您自己的 AWS 账户或 Google Cloud 项目中运行 MIOSA 工作线程容量，而 MIOSA 仍然是控制平面。

当您出于治理、成本或政策原因必须将计算保留在自己的云帐户中，但仍需要 MIOSA 的产品和编排时，请使用它。

在 MIOSA 中，BYOC 是受管理的员工能力。它与连接各个计算机的 OpenComputers 不同。 AWS BYOC 沙盒容量是一个封闭的私有预览。

相关：工作池、客户云区域、OpenComputers、控制平面、混合基础设施

### 能力

功能是资源表示它可以执行的操作，例如运行命令或流式传输桌面。

在依赖目标之前检查功能。两台机器可以共享相同的界面但支持不同的操作。

在 MIOSA 中，无头服务器无需桌面流即可报告命令执行情况。在选择运行地点之前，请先进行基础设施能力比较。

相关：主机、准备情况、计算机、安置

### 容器

容器是一个应用程序，打包了它运行所需的所有内容，并在计算机上自己的有限空间中运行。许多容器可以共享一台机器。

在 MIOSA 上，您在两个地方遇到容器：Docker 在大多数 Sandbox 模板中工作，而 App Engine 将您发布的应用程序作为工作区主机上的容器运行。

在 MIOSA 中，`docker run --rm alpine echo hello` 在沙箱中工作。容器不是沙箱：沙箱是可以运行容器的整个虚拟机。

相关：Dockerfile、App Engine、microVM、沙箱

### 控制平面

控制平面是 MIOSA 服务，它决定并记住：应该存在什么、谁可以做什么、工作放在哪里以及每个资源应处于什么状态。

是大脑，不是肌肉。实际运行工作负载的机器属于数据平面。

在 MIOSA 中，当您创建沙箱时，控制平面会记录它、检查策略并选择主机。通过 BYOC，MIOSA 保留控制平面，而工作人员则坐在您自己的云帐户中。

相关：数据平面、所需状态、放置、自带云 (BYOC)

### 客户云区域

客户云区域是在您自己的云帐户或项目中运行的经批准的工作区域。这是您拥有的能力，通过 MIOSA 进行控制。

当策略规定工作负载必须在您控制的特定云位置中运行时，请使用它。

在 MIOSA 中，您可以在预检检查后使用 `miosa cloud region` 命令创建一个，并且放置可以将其作为目标。它不像 `us-west` 那样是 MIOSA 自己的区域之一。

相关：自带云 (BYOC)、工作池、放置

### 数据平面

数据平面是实际工作和数据处理发生的地方：执行代码和接触文件的主机、机器和运行时。

对于诸如“我的数据去了哪里？”之类的问题很重要。控制平面授权、编排；数据平面进行处理。

在 MIOSA 中，命令在数据平面中的沙箱主机上运行。对于 OpenComputers，这可以是您拥有的硬件。

相关：控制平面、数据驻留、主机

### 专用 vCPU

专用 vCPU 大小提供其完全拥有的服务 CPU。每个 vCPU 都是主机的一个硬件线程，固定到您的服务，并且从不与其他工作负载共享。

当您需要稳定的 CPU 并且没有嘈杂的邻居时，请使用它。每个 vCPU 内存为 4 GiB，商业版和企业版提供专用大小。

在 MIOSA 中，大小的命名方式类似于 `dedicated-2`（2 个 vCPU，8 GiB）。

相关：服务、副本、计划、主机

### 鞭炮

Firecracker 是 MIOSA 沙箱默认运行的开源 microVM 引擎。 microVM 是一种非常小的、快速启动的虚拟机。

这就是为什么沙盒感觉像一台真正的计算机但可以立即启动，以及为什么一个客户的工作负载无法达到另一个客户的工作负载的原因。

在 MIOSA 中，Firecracker 是默认的沙箱引擎：如果你从未设置过 `runtime_profile`，你会得到 `standard`，即 Firecracker。 MIOSA 自己的引擎 SOMA 处于抢先体验阶段。相关：SOMA、Sandbox、microVM、runtime_profile（沙箱字段）

### 心跳

心跳是来自连接主机的常规小消息，表示“我仍然在这里并与 MIOSA 交谈”。

它告诉你特工还活着。它并不能证明应用程序、桌面或特定命令有效。

在 MIOSA 中，将新的心跳加上完整的命令视为主机可用的证据。

相关：主机、准备情况、OpenComputer

### 主持人

主机是实际运行工作的物理机或虚拟机。它的运行时间和它报告的功能决定了它可以执行哪些操作。

您很少会在 MIOSA 管理的车队中选择一辆。使用 OpenComputers，您可以将自己的计算机注册为主机并通过主机 ID 对其进行寻址。

在 MIOSA 中，沙箱、桌面会话或部署在主机上运行，​​但不是主机。 `miosa host get <host>` 显示其状态、平台、区域、标签和功能。

相关：功能、工作池、心跳、主机密钥、OpenComputer

### 混合基础设施

混合基础设施意味着同时使用多种位置，例如 MIOSA 管理的计算和您自己的服务器，每个工作负载均按策略放置。

使用它来保留基础设施上的敏感或受管理的工作，并在 MIOSA 上运行其余的工作。

在MIOSA中，混合并不意味着自动溢出或迁移。您选择显式放置并检查每个目标的功能。

相关：放置、自带云 (BYOC)、MIOSA 管理的基础设施、OpenComputers

### 隔离

隔离是工作负载与其他一切（其他客户、主机和其他工作负载）之间的墙。它可以阻止一件事读取或破坏另一件事。

它可以让您安全地运行不受信任或人工智能编写的代码。不同的资源类型使用不同的边界，因此不要假设它们都是相同的。

在 MIOSA 中，每个沙箱都是自己的 microVM，具有自己的内核，并且生产运行时与其他租户和构建沙箱隔离。

相关：SOMA、Firecracker、网络策略、沙箱

### 微虚拟机

microVM 是一个精简的虚拟机。它的行为就像一台完整的计算机，具有自己的操作系统内核，但可以立即启动并且占用很少的开销。

这就是为什么 MIOSA 可以为每个沙箱和计算机提供一台真正的、独立的机器，而不是共享一台。一个工作负载无法看到另一个工作负载的文件或进程。

在 MIOSA 中，Sandbox 默认运行在 Firecracker microVM 上，SOMA 是 MIOSA 自己的引擎。

相关：Firecracker、SOMA、隔离、沙箱

### MIOSA 管理的计算机

MIOSA 管理的计算机是其底层容量和生命周期由 MIOSA 运行的计算机。这是您创建时的默认类型。

使用它进行交互式桌面工作，无需维护硬件。 MIOSA 会保留可用的桌面容量，以便可以快速分配新的桌面容量。

在 MIOSA 中，`miosa computer create my-desktop` 为 1。相比之下，OpenComputer 是您拥有的机器。

相关：计算机、OpenComputer、MIOSA 管理的基础设施、热容量

### MIOSA 管理的基础设施

MIOSA 管理的基础设施是 MIOSA 为您运行的计算容量和主机：硬件、网络、主机生命周期、容量和放置。

使用它来启动而无需拥有服务器。您创建资源，MIOSA 使机器保持运行。

在 MIOSA 中，每个默认的沙箱和计算机都在这里运行。您对您的申请和数据负责； MIOSA 负责处理机器。

相关：MIOSA 管理的计算机、共同责任、混合基础设施

### 本地

本地是指在您自己的站点运行的硬件：办公室、实验室或数据中心。它命名了一个位置，而不是一个产品。

当机器与您实际生活在一起时（可能是为了数据规则或因为您已经拥有它），请使用它。

在 MIOSA 中，您可以通过 OpenComputers 连接本地服务器。这个词并不意味着 MIOSA 的自托管副本。

相关：本地服务器、OpenComputers、数据驻留

### 本地服务器

本地服务器是您在自己的站点上运行的服务器，可以通过 OpenComputers 连接到 MIOSA。

因此，单个计算机也可以是一台 OpenComputer。您对其硬件、电源、操作系统和网络负责。在 MIOSA 中，您安装主机智能体、注册计算机并使用 `hostname` 命令进行验证。请参阅[连接您的第一个服务器](/docs/opencomputers/connect)。

相关：本地、OpenComputer、OpenComputer

### OpenComputers

OpenComputer 是由您控制并通过 OpenComputer 连接到 MIOSA 的机器：服务器、工作站、GPU 盒或现有托管服务器。

它可以在任何地方运行。连接模型未定义其物理位置。

在 MIOSA 中，您的实验室服务器一旦注册，就会显示为可以在其上运行命令的 OpenComputer。它与 BYOC 工作人员容量不同。

相关：OpenComputers、计算机、MIOSA 管理的计算机、主机密钥、主机指纹、本地服务器、隧道

### OpenComputers

OpenComputers 是一个用于将您已有的机器连接到 MIOSA 并远程操作它们的系统：命令、容器、隧道、CI 运行程序、备份和智能体工作。

当工作必须在您控制的硬件上运行时使用它。您安装主机智能体，它打开出站连接，MIOSA 将计算机作为主机进行管理。

在 MIOSA 中，连接机器不会在其上安装完整的 MIOSA 控制平面。您保留硬件、操作系统以及智能体可能达到的目标的决定。

相关：OpenComputer、本地服务器、主机密钥、自带云 (BYOC)、数据驻留

### 安置

放置是决定合格工作负载将在何处运行：允许的主机或池。

它遵循策略和功能，例如区域、大小以及主机是否支持您的需求。您通常不会直接选择主机。

在 MIOSA 中，调度程序将工作负载的 CPU、RAM 和区域需求与队列的可用容量进行匹配。在混合设置中，策略可以将受管理的工作负载保留在您自己的基础设施上。

相关：工作池、混合基础设施、能力、控制平面

### 地区

区域是沙箱或计算机运行的地方。每一种资源都在一个区域中创建，并在其生命周期内保留在那里。

首先根据数据规则进行选择，然后根据与用户或 CI 的紧密程度进行选择，以便连接更快。对于大多数人来说，美国三个地区的表现大致相同。

在 MIOSA 中，区域为 `us-west`（洛杉矶，默认）、`us-east`（纽约）和 `us-mia`（迈阿密）。 `miosa regions` 显示可用内容以及是否有容量。

相关：放置、数据驻留、沙箱、计算机、客户云区域

### 复制品

副本是同时运行的动态应用程序的多个相同副本之一。更多副本可处理更多访问者，并在其中一个失败时保持应用程序正常运行。

默认情况下，动态服务有一个。当您需要更多容量或弹性时提高它。

在 MIOSA 中，您设置 `desired_replicas`，协调器会在主机之间以及可能的情况下跨区域传播副本。流量在健康的副本之间共享。

相关：运行时实例、动态部署、协调

### runtime_profile (sandbox field)

create-sandbox 请求正文中用于选择引擎的字段。 `standard` 是 Firecracker（默认值，无需额外批准），`soma` 是 SOMA（需要启用的策略和容量），`auto` 让策略决定并可以选择 Firecracker。省略该字段将被完全视为 `standard`。

相关：Firecracker、SOMA、沙盒、运行时配置文件

### 共同责任

共同责任是由谁负责什么的书面划分：MIOSA、您或云提供商，具体取决于您的工作负载运行的位置。

在选择基础设施之前请阅读它。通过 MIOSA 管理的计算，MIOSA 运行机器。使用 OpenComputers，您拥有硬件和操作系统。通过 BYOC，您拥有云帐户，MIOSA 运行控制平面。

在每种模型中，应用程序所有者都拥有应用程序数据和备份策略。

相关：MIOSA 管理的基础设施、自带云 (BYOC)、OpenComputers

### 索玛

SOMA，即安全优化机器架构，是 MIOSA 自己的开源虚拟机监视器，在 Apache 2.0 下用 Rust 编写。它为沙箱提供了自己的硬件隔离的 Linux 机器。你不运行它。 MIOSA 为您操作 SOMA，并且处于早期访问阶段，按组织启用。它的存在是为了让 MIOSA 掌握机器准备好运行命令的确切时刻。

在 MIOSA 中，SOMA 通过恢复经过认证的快照来启动沙箱，然后在调用准备就绪之前证明来宾还活着。

相关：Firecracker、Isolation、Sandbox、Snapshot、microVM、runtime_profile（沙箱字段）

### 热容量

热容量是提前做好计算准备的，因此新计算机或沙箱可以更快地启动，而不是冷启动。

这就是为什么托管计算机可以在热路径上在一秒钟内移交的原因。不保证每种尺寸都能立即供货。

在 MIOSA 中，托管队列在每台主机上保留就绪的桌面和沙箱插槽。

相关：计算机、沙箱、MIOSA 管理的计算机

### 工作池

工作线程池是一组兼容的主机，它们可以在放置策略下运行某种类型的工作负载。

它为 MIOSA 提供了一组可供调度的机器。仅仅注册是不够的：成员必须兼容并能够完成工作。

在 MIOSA 中，自带云区域是您的 AWS 账户或 Google Cloud 项目内的工作人员容量池。

相关：主机、放置、自带云 (BYOC)、功能
