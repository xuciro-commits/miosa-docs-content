通过此页面，客户可以清楚地了解今天已准备好生产的内容、可供选定合作伙伴使用的内容以及仍在路线图上的内容。

> 当平台功能更改发布阶段时，我们会更新此页面。

## 发布阶段

|舞台|意义|
|---|---|
| **普遍可用** |通过记录的 API 和正常支持路径支持生产使用。 |
| **合作伙伴预览** |在我们完成完善、SDK 奇偶校验或操作手册时可供批准的客户使用。 |
| **硬化中** |已建成或部分可用，但尚未准备好作为稳定的公共表面。 |
| **计划** |在路线图上，尚未可用于生产用途。 |

## 一般可用

- **沙箱**：创建独立的 Linux 工作区，用于代码生成、构建步骤、测试运行、长时间运行的命令、文件操作和实时预览。
- **实时预览**：在公共预览 URL 上公开正在运行的进程，并使用私有预览令牌来实现嵌入式产品体验。
- **发布和回滚**：将沙箱变成持久的部署版本，升级它，列出版本，并在需要时回滚。
- **托管数据服务**：使用 Postgres、MySQL、Redis、Qdrant、对象存储、每个项目身份验证以及将凭据注入运行时的持久卷。
- **白标平台**：使用外部 ID、浏览器令牌、自定义品牌、预览域、Webhook 和使用情况汇总将 MIOSA 构建到您自己的产品中。

## 合作伙伴预览

在我们继续完善公共文档和 SDK 奇偶校验的同时，这些界面正在供选定的客户使用。

|表面|当前范围 |
|---|---|
| **计算机** |用于浏览器自动化、屏幕截图循环和计算机使用智能体的完整 Linux 桌面。 |
| **动态部署** |从沙箱发布创建的生产服务器进程。 |
| **Docker 主机** |工作区范围的容器运行时，适用于需要 Docker、服务器进程、后台工作人员或数据库支持的生产托管的应用程序。 |
| **租户部署域** |生成的应用程序的品牌应用程序域与沙箱预览域分开。路由存在；租户级自助服务仍然由操作员协助，而确切的部署域是自助服务。 |
| **外部计算机提供商** |将第三方计算机提供商引入相同的 MIOSA 计算机抽象。 |
| **评估** |使用可重现的任务、跟踪和评分进行桌面和智能体工作流程基准测试。 |

## 强化中

|面积 |状态 |
|---|---|
| **桌面计算机配置** |计算机在停止、恢复和恢复失败时保留磁盘和快照。启动延迟和流准备情况继续得到强化。 |
| **动态运行时路由** |动态运行时可以在候选版本构建时保持活跃的健康版本的服务。路由证据和自动恢复继续得到强化。 |
| **Docker 主机队列维护** |主机升级可保留部署记录和所需状态、恢复所需运行的应用程序，并在主机返回活动服务之前验证工作负载。 |
| **客户云区域** | AWS 和 Google Cloud 基础已经存在，但生产部署仍然取决于真实的提供商金丝雀和每个主机的验收证据。 |
| **托管数据恢复** |数据库 ID、凭据、卷、绑定和所需状态可以在主机维护后继续存在。恢复可见性继续扩大到整个产品表面。 |
| **部署证明** | CLI、TypeScript SDK、Python SDK 和 Go SDK 公开了证明检查。 Java 和 Elixir 的比价仍在进行中。 |
| **SDK 平价** |今天，Python 和 TypeScript 是最深入的。随着时间的推移，Go、Java、Elixir 和 UI 包的覆盖范围也相同。 |
| **跨工作空间分析** |资源归属已上线。更高级别的仪表板和计费视图正在扩展。 |

## 第 4 版中有哪些内容

客户现在可以信赖的最新平台变化。
每一项都是结果，而不是对未来工作的承诺。

| 变更 | 结果 |
|---|---|
| 磁盘损坏防护 | 把内存快照恢复到快照之后已扩容的磁盘上会被拒绝，而不是损坏文件系统。该防护已在控制平面和所有主机上生效。 |
| 来宾与内部网络隔离 | 除了托管数据库代理网段之外，沙箱无法访问平台自身的网络。阻止较旧的允许规则覆盖拒绝规则的 Firecracker 规则排序已在整个机群生效，并且 SOMA 已经强制执行了该规则。 |
| 白标员工的预览回退 | 白标组织自己的员工的预览访问会回退到经过身份验证的控制台路径，而不是直接失败。 |
| 磁盘大于预构建槽位 | 请求的磁盘大于预构建槽位时，会以请求的大小启动，而不是失败或返回错误的大小。 |
| Learn 积分冷却 | 过期的 Learn 尝试从过期时间开始计时，而过期且没有任何答案的尝试不再算作失败。 |
| 函数池 | 每台主机的函数池已部署但尚未启用：它还不是面向客户的能力。 |
| SOMA 目录准确性 | 运行时目录不再为 SOMA 宣称暂停或快照，而 SOMA 两者都不支持。 |

## 计划中

|能力|笔记|
|---|---|
|原生 GPU 沙箱 |目标是 2027 年初，适用于需要加速推理或渲染的工作负载。 |

| OTLP 出口 |专为希望在自己的可观察性堆栈中跟踪平台的团队而设计。 |
|测试模式 API 密钥 |计划将生产计费与集成测试分开。 |

## 有意的产品边界

MIOSA 专注于人工智能生成的软件、独立执行、实时预览、桌面自动化、白标 SaaS 基础设施和持久部署。它是故意不：

- **托管 Kubernetes**。沙盒和部署涵盖了人们原本会使用 K8 的工作负载。
- **通用 VPS 托管**。计算始终与租户身份（工作空间或 `external_workspace_id` 相关联）。
- **加密货币或区块链原语**。
