服务是项目运行的应用程序。
服务属于四种常见类型之一，此外还有定时任务和数据库服务：

| 类型 | 说明 |
|---|---|
| Web 服务 | 在公共地址上提供 HTTP 服务的进程。 |
| Worker | 没有端口、没有地址的进程。它会一直运行，直到停止。 |
| 私有服务 | 没有公共地址的进程。服务之间的私有网络尚未提供，因此其他服务无法通过名称访问它；它可以通过托管数据库的连接变量访问这些数据库。 |
| 静态站点 | 从边缘提供预构建文件。 |
| 定时任务 | 按五字段 cron 计划执行的命令，带运行历史和输出。 |
| 数据库服务 | 绑定到项目的托管 Postgres 或 Redis。 |

每个服务都属于一个项目和一个环境。
项目创建时自带一个 `production` 环境；您可以添加 `staging` 或任何其他需要的环境。

## 服务的组成

- **发布。** 每次部署都是一个不可变的发布，带编号、状态，失败时还有原因。
- **变量。** 静态加密存储，读取时遮盖，并且可以引用另一个服务、共享变量或生成的密钥。
- **地址。** 每个服务都会分配一个私有名称。Web 服务或静态站点还可以拥有一个公共地址。
- **设置。** 副本数、区域、启动命令、健康检查、重启策略、卷和空闲休眠。

## 生命周期

1. 使用一个来源创建服务：Git 仓库、容器镜像或上传的归档。
2. 部署它。MIOSA 会构建并启动一个发布。
3. 当发布的副本通过健康检查后，该发布变为 `active`。
4. 再次部署以更改它，或回滚到较早的发布。回滚会提供之前构建的镜像，因此不会重新构建。

## 从 Railway 迁移

模型可以直接对应：

| Railway | MIOSA |
|---|---|
| 项目 | 项目 |
| 服务 | 服务（Web 服务、Worker、私有服务或静态站点） |
| 环境 | 环境 |
| 部署 | 发布 |
| 变量和共享变量 | 变量和共享变量 |
| 自定义域名 | 公共地址 |

`miosa service` 用于操作服务。
服务使用 `/projects/:id/services` 和 `/services/:id`；独立的 Deploy 产品保留自己的 `/deployments` 路由。
