## 延迟

桌面方法通过经过身份验证的 HTTP RPC 同步运行。从 MIOSA 边缘出发的典型往返行程：

|方法类型|典型延迟 |
|---|---|
|单击、按键、滚动、键入 | 30-80 毫秒 |
|截图| 100-300 毫秒（压缩限制）|
|窗口列表| 50-100 毫秒 |
| `bash()` / `python()` | 50 毫秒加上命令执行时间 |

对于高频循环，优先使用 `bash()` 进行多步操作，而不是许多单独的 GUI 调用。
`GET /desktop/window-state` 一起返回屏幕截图和可访问性树，因此感知需要一次往返而不是两次。

## 坐标空间

坐标是原点位于左上角的屏幕像素，与 `GET /desktop/screen-size` 和 `GET /desktop/cursor` 报告的内容匹配。
视觉模型可能会显示按比例缩小的屏幕截图；在发送操作之前将其输出映射回屏幕像素。

## 截图

截图是PNG格式的。
完整的桌面映像通常有几百 KB；区域更小。
当仅需要屏幕的一部分时，请使用 `/desktop/screenshot/region`；当您同时需要像素和结构时，请使用 `window-state`。

## 尺码

|尺寸| vCPU |内存 |磁盘 |典型用途|
|---|---|---|---|---|
| `xs` | 1 | 2GB| 10GB|轻量级无头任务 |
| `small` | 2 | 4GB| 20GB| **默认**单个智能体和基本浏览 |
| `medium` | 4 | 8GB| 40GB|桌面应用程序更重，页面加载更快 |
| `large` | 8 | 16GB| 80GB|多应用程序、大上下文工作负载 |
| `xl` | 16 | 32GB| 160GB|密集并行|

GPU 对加速桌面和 GPU 感知工作流程的支持取决于计划。

## 生命周期

创建创建配置；配置准备就绪后即可运行；停止时运行变为停止，启动时返回运行。

运行用于恢复主机维护；恢复后将继续在恢复后运行。

恢复失败时恢复会出错。

运行或停止将在删除时删除。

停止计算机会暂停计算并保留文件系统和浏览器配置文件。
重新启动将从该状态恢复。
桌面端点仅在计算机处于 `running` 时接受请求；否则返回 `409 COMPUTER_NOT_RUNNING`。

## 身份验证

桌面方法需要与所有其他 MIOSA 资源相同的工作区 API 密钥。
称它们为服务器端。
对于浏览器端控制，创建一个作用域令牌而不是传送 API 密钥 - 请参阅[嵌入和流式传输](/docs/computers/embedding)。

> **警告：切勿暴露 API 密钥**
>
> 在后端创建流 URL 和范围令牌。
> 仅将短期 URL 或令牌发送到浏览器。

## 速率限制

速率限制因密钥、租户策略和端点系列而异。
尊重 `X-RateLimit-*` 和 `Retry-After` 响应标头。
单个桌面操作速度很快，但紧密的感知-操作循环仍然会发出许多请求；工作不需要像素的批处理。

## 错误

|状态 |代码|原因 |
|---|---|---|
| `409` | `COMPUTER_NOT_RUNNING` |计算机已停止、配置或恢复 |
| `502` | `AGENT_UNAVAILABLE` |电脑内的智能体没有回答 |
| `429` | - |限价|
