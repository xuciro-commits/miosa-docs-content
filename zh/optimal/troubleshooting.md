每个条目都从您所看到的内容开始，然后是修复。

## 在控制台中

### "Optimal runs on credits"

Optimal 需要正信用余额，而你的信用余额是空的。
按“**添加积分**”或“**升级**”以获得包含积分的计划，然后再次发送。
在大脑选择器中，相同的状态显示“添加积分以使用最佳值”。

运行框架或保存的智能体不使用其模型的积分，因此您仍然可以使用其中之一。

### “选择或创建一个工作区来开始隔离的最佳聊天。”

未选择工作空间。
在工作区切换器中选择一个。
在**所有工作区**下，Optimal 会读取每个工作区，但会在更改任何内容之前询问使用哪一个工作区。

### 调查呈灰色

调查始终在最佳大脑上运行。
聊天的大脑是一个工具或一个保存的智能体，并且聊天保留了它的大脑。
使用 **New** 开始新的聊天并选择 Optimal。

### 大脑选取器不会改变

大脑在收到第一条信息后就固定下来了。
选择不同的大脑开始新的聊天。

### 运行框架显示“未连接”或“需要重新登录”

按大脑选择器中相应行上的 **连接** 或 **重新连接**，登录，然后返回“最佳”。
请参阅[利用和验证](/docs/agents/harnesses)。

### “此聊天的机器已删除。选择另一个，或让 Optimal 选择。”

与聊天绑定的沙箱或计算机不再存在。
在机器菜单中选择一台机器，或在构建模式下发送并选择**新沙箱**。

### “...保存在此聊天的机器上：选择一个沙箱或计算机，然后再次发送。”

该文件不是图像或文档，因此它被写入聊天的机器，而聊天没有。
在机器菜单中选择一台机器，然后再次发送文件。
每个文件的大小限制为 10 MB，每个聊天的文件大小限制为 25 MB。

### “被打扰了。回复提前停止了。”

回复还没说完就被切断了。
按注释旁边的**重试**；聊天会保留之前的所有内容。

### “无法接管。请重试。”或“无法归还。请重试。”

机器没有及时应答。
稍等片刻，然后再次按 **接管** 或 **交回**。
检查 **机器** 选项卡以查看机器是否正在运行。

### 无法发布

机器必须正在运行才能发布。
从 **机器** 选项卡或机器菜单恢复它，然后再次按 **发布**。

### 上下文表是红色的

该聊天已使用大部分 1M 令牌上下文。
不需要任何东西：Optimal 将旧部分折叠成自己的摘要，并在折叠时显示“正在压缩上下文...”。

## 通过 API

|你得到|修复 |
|---|---|
| `401` 和 `MISSING_TOKEN` |发送 `Authorization: Bearer <Optimal token>`，而不是您的 API 密钥 |
| `401` 之前有效的通话 | Optimal 代币在 10 分钟后过期；铸造一个新的|
| `403 FORBIDDEN` 铸造时 |授予 API 密钥 `osa:write` 权限 |
| `403 API_KEY_WORKSPACE_BOUND` |为密钥绑定到的工作区创建令牌 |
| `403 approval_scope_required` |为 API 密钥授予 `osa:approve` 权限，然后铸造一个新令牌 |
| `402 OPTIMAL_CREDITS_REQUIRED` |添加积分或升级 |
| `404 session_not_found` |聊天id错误、已删除、或在其他工作区；检查令牌的工作区 |
| `409 machine_switch_requires_confirmation` |使用 `"confirm_switch": true` 再次发送消息 |
| `409 machine_unavailable` |启动机器，然后重试 |
| `409 no_machine` 上传 |首先使用 `POST /sessions/{id}/machine` 绑定机器 |
| `415 unsupported_media_type` |添加 `Content-Type: application/json` |
| `429 rate_limited` |等待 `Retry-After` 秒 |
|一条不显示任何内容的流 |在发送之前打开流，或从 `GET /sessions/{id}/messages` 读取已完成的回合。|

请参阅每个端点的[最佳 API](/docs/optimal/api)。
