MIOSA 计算机使用托管机群上的就绪容量，因此无需等待完全冷启动即可分配新桌面。
产品目标很简单：单击**启动**，然后在热路径上大约 800 到 900 毫秒内收到交互式桌面。

## 验证结果

2026 年 8 月 6 日测量的生产金丝雀完成了 10 次启动中的 10 次，并在中值 **740 毫秒**内达到了浏览器就绪桌面。

|相|时间 |
|---|---:|
|成功推出 | `10 / 10` |
|创建响应中位数 | `348 ms` |
|创建对浏览器就绪桌面中位的请求 | **`740 ms`** |
|创建对浏览器就绪桌面 p90 的请求 | **`809 ms`** |
|最慢的样本 | `942 ms` |

每个金丝雀都使用暖路径，不需要重新启动回退。
浏览器使用捆绑的直接 noVNC 客户端，并且 `Live` 需要其真实的 RFB 连接事件。
启动路径在创建请求的同时温暖了未来的观众传输，并保留了路线注册竞赛的有界重试。

> **注意：如何读取这个数字**
>
> 10 个样本的结果是过时的生产金丝雀结果，而不是通用的延迟保证。
> 区域、队列容量、网络延迟、映像选择和冷路径回退可能会更改启动时间。

## 浏览器就绪意味着什么

MIOSA 不会仅仅因为计算机的数据库记录存在或其生命周期显示 `Running` 就将其称为就绪。
浏览器准备就绪需要完整的查看路径才能工作。

1. 创建请求声明准备好的桌面容量。
2. 流 API 返回一个短暂的经过身份验证的查看者 URL。
3. 捆绑的查看器客户端直接连接到经过身份验证的 VNC WebSocket。
4. VNC WebSocket 使用流令牌进行升级。
5. 浏览器呈现一个可用的桌面框架。
6. 打开计算机工作区使桌面保持安装状态并连接其终端。

托管队列在每台主机上保留单独的储备：20 个就绪的桌面插槽和 20 个就绪的沙箱插槽。
仅当默认 MIOSA 壁纸可见后，桌面插槽才会进入就绪池。
在索赔期间，在将计算机交给用户之前，会应用租户壁纸和桌面品牌。

- **无虚假实时状态**：浏览器错误文档或失败的 iframe 导航不得标记为实时桌面。
- **经过身份验证的切换**：流 URL 是短暂的，并且范围仅限于所选计算机。
- **工作区连续性**：画廊到工作区的转换保留了观看者的切换，而不是请求冲突的会话。

## 应用程序集成

从后端请求计算机流 URL，并仅将短期 URL 传递到浏览器。
嵌入 API 返回的经过身份验证的查看者 URL，而不是从计算机 slug 重建桌面 URL。

您的 UI 应分别表示这些状态：

|状态 |意义|推荐用户界面 |
|---|---|---|
| `provisioning` |正在分配容量或客人已准备就绪 |显示有限进度 |
| `running` 查看器准备就绪 |桌面和流路径可用|显示 `Live` 并显示查看器 |
| `paused` |持久状态存在，但活动桌面已停止 |提供简历 |
|查看器不可用 |生命周期和观众可达性不一致 |显示可操作的错误并重试控制 |
|失败 |供应或启动失败 |显示后端错误和恢复操作 |

不要仅将 iframe 从其通用 `load` 事件提升为 `Live`。
浏览器也会针对自己的网络错误文档触发该事件。

## 故障排除

### 卡显示正在运行，但查看器显示主机不可用

将查看者可达性视为用户可见状态的权威。
刷新计算机生命周期，然后重试流请求。
如果不匹配现象仍然存在，请联系支持人员并提供计算机 ID、区域和大致创建时间。

### 查看器页面返回503

公共查看器网关无法到达活动计算智能体或分配的主机。
这是平台路由故障，而不是证明您的文件或计算机记录丢失。
重试一次，如果问题仍然存在，请联系支持人员。

### 流请求返回409计算机当前不处于可流式生命周期状态。
刷新其状态并在 API 报告 `paused` 时恢复。
不要在不重新读取生命周期的情况下无限期地重试。

### iframe 加载但没有出现桌面

确认您嵌入了 API 返回的经过身份验证的查看者 URL。
不要替换原始桌面条目 URL 或等待未记录的跨框架事件。
